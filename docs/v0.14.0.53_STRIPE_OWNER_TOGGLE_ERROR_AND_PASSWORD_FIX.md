## Observed issue

Owner-reported Admin UI:
- Stripe TEST account/catalog configuration 7/7 PASS.
- Cloudflare shadow testing gate "Configured" and all Price IDs present.
- Clicking **Enable Testing** returned only `Testing is unavailable; review the Admin sandbox configuration`, with Owner Test Mode remaining Disabled.

This is a real error-handling/UX defect: the frontend could not reliably tell Owner why the guarded Supabase write failed and did not invoke the site's existing password confirmation dialog.

## Verified source defects

**Root cause confirmed by a failing automated regression:** The former `getJson()` helper used `if(!r.ok||!d)` and therefore treated Supabase's valid JSON boolean `false` from `gu_staff_stepup_active_v01432r1()` as an unavailable RPC. That falsely triggered a generic HTTP error for an Owner who had *not yet* reconfirmed the password. v53 uses a response check that accepts `false` as a valid unauthenticated-stepup result, then raises the specific `PASSWORD_RECONFIRM_REQUIRED` state.

1. Cloudflare `POST /api/gu39-sandbox` calls `gu_staff_stepup_active_v01432r1()` before the switch. The existing password/Turnstile dialog module `admin-password-confirm-v01432r1.js` intercepts **Supabase client .rpc** errors, not raw `fetch('/api/gu39-sandbox')` from the Stripe console.
2. The client simply printed the API's generic text. The backend translated all non-allowlisted Supabase RPC failures into a generic 403; a separate expired toggle timestamp, role rejection, missing DB RPC or failed audit-log transaction could not be differentiated.
3. No SQL/Stripe provider deficiency is established from the generic error screenshot. Do not reapply any migrations, weaken the Owner authentication guard, or bypass the password requirement.

## Corrections

- Cloudflare maps only safe, allowlisted PostgREST RPC errors (`PASSWORD_RECONFIRM_REQUIRED`, `SETTINGS_STALE_REFRESH`, `OWNER_REQUIRED`, `STAFF_REQUIRED`, `INVALID_SETTINGS`) into stable error codes.
- Infrastructure failures are categorized as `STAFF_STEPUP_CHECK_UNAVAILABLE`, `SHADOW_TOGGLE_RPC_UNAVAILABLE`, `SHADOW_TOGGLE_AUTH_REJECTED`, `SHADOW_TOGGLE_DATABASE_REJECTED`, avoiding raw PostgreSQL messages/customer data.
- Client receives `PASSWORD_RECONFIRM_REQUIRED`: opens the **existing** password + human verification UI `GroundUpAdminPasswordConfirm.ensure()` and **retries exactly once**. If password dialog fails/cancels, no toggle runs.
- Client tells Owner which exact component rejected other failures and whether to refresh stale data. No repeated approvals, no changes to existing Stripe products or pricing.
- Versioned Admin bundle cache busting `?v=014053`; release-manifest/config/roadmap/SW aligned. Regression tests cover backend guards and Owner browser workflow.
- The actual Supabase `gu39_sandbox_owner_toggle` and `gu_staff_stepup_active_v01432r1` authorization remain intact.
