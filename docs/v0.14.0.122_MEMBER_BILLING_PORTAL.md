## Design

A **server endpoint** creates Stripe Billing Portal sessions only for a member-owned `site_subscriptions` or `user_tool_passes` row with provider `STRIPE_MANAGED`, signed GU58 webhook provenance, and a stored subscription ID. It verifies the Supabase bearer token/account kind, checks the Stripe merchant account, fetches the real LIVE Stripe subscription (rather than trusting a client-supplied `cus_` identifier), resolves its customer ID, and creates a portal session returning to the site's own Purchases page. The UI uses a button on each eligible membership/tool row. There is no permanent unsafe `billingPortalUrl`.

Critical: Checkout feature flags do **not** gate cancellation. If an owner temporarily disables new payment acceptance, existing members must still be able to manage their recurring charges. Suspension/restriction also does not block billing management.

No new SQL is required: existing signed event metadata and subscription IDs are used. The Stripe merchant must configure the Customer Portal with permitted subscription cancellation and payment methods; source code alone does not establish that Stripe Portal is enabled or compliant. Refunds, cancellation state and access changes remain the responsibility of signed webhook processing, not a browser redirect.

## Production acceptance

Create a real paid test account only with consent/controlled cost, verify member 1 can open only their own live subscription, member 2 cannot, suspended member can cancel, and Stripe account ID/livemode are correct. Verify portal handles canceled subscriptions, invoices, payment method changes, cancellation confirmation, failed payment, and the signed webhook subsequently changes account access. If portal configuration is missing, show a support path instead of silently accepting an inaccessible cancellation. No live charge or portal session was made in source tests.

## Legal/operational

Customer-friendly cancellation must be functional, prominent and consistent with applicable subscriptions law and Stripe settings; obtain legal review. The provider may require configuration for cancellation flows, invoices and emails. Do not claim complete subscription lifecycle acceptance merely because this entry point is implemented.
