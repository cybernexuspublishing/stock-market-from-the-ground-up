## New in v0.14.0.51: one-click Owner preflight

Go to **Admin Control Center → Payments & Billing → Stripe Payment Testing → Run Payment Test Preflight**.

This read-only function checks:
1. Stripe TEST secret binding format.
2. Stripe TEST webhook signing-secret binding format (presence, not whether it matches provider).
3. Stripe account matches the known eight-product TEST catalog account.
4. All eight distinct existing Stripe TEST Price ID mappings are configured.
5. Existing Supabase Owner shadow-test settings row is readable via the server-only key.
6. Exactly one enabled Stripe TEST webhook destination matches the **origin from which Owner is accessing this website** plus `/api/gu39-stripe-webhook`.
7. That destination subscribes to all eight event types:
   - `checkout.session.completed`
   - `checkout.session.async_payment_succeeded`
   - `invoice.paid`
   - `invoice.payment_failed`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `charge.refunded`
   - `charge.dispute.created`

Preflight is **READ ONLY**, authenticated Owner-only, and can run while both testing gates are OFF. It does not expose secret values, create Stripe products or sessions, change database rows, enable the test gates, or grant real entitlements.

A 7/7 preflight is **necessary but not sufficient** for TEST checkout readiness: Stripe does not disclose webhook signing secrets after creation, and Managed Payments product/account eligibility is verified only during a real authorized TEST checkout.

## Interpretation of failure modes

| Owner preflight output | Corrective target |
|---|---|
| TEST secret missing/invalid | Encrypted Cloudflare Production `GU39_STRIPE_TEST_SECRET_KEY`, TEST key rotation and deployment |
| Signing secret missing/invalid | Encrypted `GU39_STRIPE_TEST_WEBHOOK_SECRET` copied from the actual enabled TEST destination |
| Account mismatch | Wrong Stripe TEST account; do not recreate products |
| Price map not valid | Existing eight Price IDs in `GU39_STRIPE_TEST_PRICE_MAP_JSON`; preserve SKUs and prices |
| Supabase controls unreadable | Verify Production server-only Supabase key and GU39 isolated schema |
| Webhook destination absent | Fix Stripe TEST event destination URL and enabled state for the current website origin |
| Event subscriptions incomplete | Enable the required events in the existing TEST webhook |
| Stripe webhook list denied | Review Stripe TEST API permissions; do not assume endpoint absent |
| All checks PASS but no webhook records | Verify real Stripe TEST checkout, endpoint secret matches and signed delivery logs |

## Engineering controls and acceptance boundaries

- Cloudflare webhook requires configured gate **and** Owner-enabled DB setting; it rejects test account mismatch, real-mode events and invalid HMAC signatures.
- GU39 tables contain isolated shadow records only. Real entitlements and commerce remain OFF.
- Do **not** run a cumulative Supabase migration as part of this test setup. The older production ACL correction is a separate P0 change and remains unapplied pending Owner review.
- Stripe tax classification is deferred as instructed by Owner; eligibility for the specifically intended **Managed Payments** product still requires a provider TEST session.
- This document is an operational checklist, not a certificate of successful real Stripe TEST checkout. Do not mark roadmap acceptance as complete without a provider receipt and matching verified shadow DB record.
