# v0.14.0.78 — Source-aware unified Account Management / Owner & Administrator governance

## Defect and prevention
The previous Owner account editor canceled only manually sourced `user_plan_grants`. After a $0.00 Stripe LIVE Checkout had issued `source='stripe_zero_monthly_qa_v72'`, clicking "Save Membership" with `FREE` returned success while `my_platform_access_for_user` continued to return `FULL_MONTHLY`. A separate legacy Admin API also allowed blind DELETE of library/learning-entitlement rows, and blind PATCH of plan/tool grants **without validating issuing source or confirming any rows changed**. Its UI duplicated, and could bypass, the new account-management policy.

The controlling invariant is **Never report a successful account access change before verifying its real effective result**. An Owner/Admin selection is an intent, not the entitlement source of truth.

## Single-account console
Use **Admin Control Center → Account Management → Manage Account**. The editor shows, for that exact member UUID:
- Profile, date of birth, real roles, account status, credential recovery and history, moderation flags, notes.
- Canonical effective plan via `my_platform_access_for_user`; manual membership plan and date changes.
- Membership grant ledger including `source`, billing provider subscriptions, legacy learning entitlements.
- Library books and source channel, tool passes and provider provenance, Book Key redemption history, website order/payment audit.
- Explicit **revoke one manual plan / manual book / manual tool** and **grant manual book/tool** controls with a 10–500 character audit reason.
- The existing **FULL_MONTHLY $0 LIVE QA → FREE** operation for the single allowlisted test member remains separate because it is not an Owner-issued plan grant.

Missing catalog, source inventory or resolver data is reported as **unavailable/unverified**; never silently interpreted as an empty inventory or FREE.

## Owner and Administrator scope
A signed-in, live `OWNER` may manage normal members and staff where appropriate; Owner-only identity controls continue to protect the last Owner, cross-Owner role changes, and irreversible deletion. A signed-in, live `ADMIN` may create and manage **ordinary real member** accounts (names, preferences, status, password resets, manual access, and membership changes). ADMIN cannot modify an Owner, another administrator, a moderator, synthetic accounts, or its own staff identity; it cannot assign staff privileges or delete accounts. Both use the same source-aware member console and audited grant/revoke RPC, with independent database verification of role/target.

**"All account items" means one accountable management interface, not authority to falsify a payment, erase regulatory billing records, or bypass external provider lifecycle controls.** Actual Stripe subscriptions must be canceled/refunded at Stripe; only a signed fulfillment event may reconcile provider-managed access. Book Key redemptions and original orders remain historical records and are not blindly deleted. Manual access can be revoked without erasing an underlying purchase, assessment result, or signed event. This preserves financial, access and educational integrity.

## Critical legacy bypass closure
Legacy `/api/admin` POST operations that previously mutated user roles, auth bans, account deletion, flags/notes, library/entitlements, manual plan and tool grants are blocked with an explicit **409** instructing users to open the unified account manager. The legacy User Accounts "Open" interaction now directs into `GroundUpAccountEditor.openById`. Global site/catalog controls, content and commerce reporting are not affected. No new route may reinstate blind `return=minimal` DELETE/PATCH entitlement mutation.

- Checks live Owner/Admin role and target member, refuses ADMIN→staff/Owner edits, refuses self-mutations, locks the target account row namespace.

Apply in **Supabase SQL Editor** after reviewing current production schema, then deploy the merged GitHub commit on Cloudflare. Supabase SQL execution and authenticated production membership mutations were NOT performed through GitHub.
