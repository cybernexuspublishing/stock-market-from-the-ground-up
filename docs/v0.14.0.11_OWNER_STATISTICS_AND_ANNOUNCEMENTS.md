# v0.14.0.11 — Source Changes and Acceptance

## Scope

1. Responsive form layouts for Owner instructor question bank and Grant Web Solutions client draft editor. No contract changes.
2. Community statistics: Live = real registered and last-60-minute activity. Demo Range = rotating sampled numbers within configured bounds, updating at deterministic time intervals varying from 1 to 30 minutes as configured by the Owner. Demo figures remain labeled **Demo** and their headings say "Example". Short label replaces previous long explanatory caption. Fixed Demo mode retained. Sampling is stable across reloads/edge workers during a time bucket. Public API includes no user identities.
3. Site Announcements: Existing table (`site_announcements` from v0.13.2 cumulative migration) used; Owner creates, edits, sets audience, enables/disables, sets local start/end converted to UTC, permanently deletes only after confirmation. The new endpoint `/api/site-announcements` checks active state, time windows and authenticated production-member audience. HTML from user content is never inserted as executable markup. Public notices display on ordinary site pages that include the shared `site.js` script. Announcements are checked at most once per minute on visible pages; dismissal lasts until the visitor closes their browser session.
4. New Owner-specific account-status check on announcement mutations; action and target audited through existing `admin_audit_log` writer.

## Deployment / Supabase

- Existing `site_announcements` table must be present (schema includes `id,title,body,announcement_type,audience,starts_at,ends_at,dismissible,active,created_by,updated_by,updated_at`). Run a read-only inspection before deploying if uncertain; do not rerun previous migrations.
- **No new write SQL migration** is required for the changes in this release.
- Production `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, and server-only `SUPABASE_SECRET_KEY` must be configured; do not expose keys in the browser.
- Server authorization of membership entitlements remains separate from these features. Never enable paid checkout or synthetic Showcase access as part of this release.
- Deploy on preview branch before production, retaining rollback commit. Cloudflare Pages build command `bash scripts/build-pages.sh`, output `public`.
- SQL B from the v0.14.0.7 Market Commons report lockdown remains **PENDING** until the two forum reporting paths are live-tested.

## Preview acceptance checklist

- Member Statistics: switch to Range mode; set registered/online bounds and 1–30 minute minimum/maximum; save, reload Admin, ensure all values persist. In public mode the changing counts are marked Demo, never Live. Switch to Live and confirm genuine last-hour activity behavior.
- Announcements: create in the future, verify not public; after start, verify shown; after end, verify hidden; disable and verify disappearance; edit to extend; test member-only notice from signed-out browser; delete a controlled test announcement and verify permanent deletion. Test protected Owner permissions using suspended and Showcase accounts.
- Test book editor and Grant Web Solutions form with long text on desktop and mobile; verify no horizontal overflow or clipping.
- Confirm market/learning pages, Admin sidebar and existing forum navigation remain intact; test with service-worker cache cleared if still seeing old version.

## Important limitations

These changes do not complete the overall 77-task platform roadmap. Administrative notices are **website banners**, not outbound email or push notifications. Permanent deletion is irreversible; Owner must confirm. Range numbers are demonstration data and cannot be advertised as real member counts. A browser's page visibility may delay notice refresh, but the server is authoritative for the temporal display window when queried.
