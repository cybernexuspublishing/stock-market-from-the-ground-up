## Confirmed code-to-migration defect
The prior Cloudflare function made a POST as an authenticated user directly to
`public.gu_staff_identity_v01431r1()`. The existing reviewed Supabase v0.14.0.31R1 migration **revokes authenticated EXECUTE** on that function. The reviewed v0.14.0.32R1 migration instead provides and **grants** a security-definer JSON facade `public.gu_staff_role_v01432r1()`, internally calling the private helper.

v0.14.0.46 updates only the authorized API path, validates `{ok:true,role:'OWNER'|'ADMIN'}`, rejects failed/MFA-ineligible roles, and clearly differentiates RPC missing (404), unauthorized (401/403), unavailable and missing authentication. It never grants direct access to the private helper and never disables MFA.

Note: `REQUIRE_STAFF_AAL2_V135=false` in Cloudflare screenshots does NOT turn off mandatory AAL2 enforced within the existing security-definer SQL staff identity function. Complete MFA step-up if prompted.
