# v0.14.0.14 — Owner Content Controls, Notifications and Instructional Forms

**Status:** Source candidate. Not deployed. No production Supabase/Cloudflare or third-party services were written or independently verified.

## Baseline and preservation
- Based on the complete v0.14.0.13 audited source ZIP; not an incremental patch.
- Retains stable active source filenames, established API route filenames, historical SQL, original account records, authorized Checkout-OFF settings, and 419 unique Historical Lab IDs.
- Build prevents publishing `data/interactive-labs.json` and uses explicit public-data allowlisting. **If GitHub still tracks that private source file, remove its tracked copy before deployment after backing it up outside Git.** Do not delete any instructor-only records in Supabase.
- No new Supabase write migration required for this release. The optional message is stored in the existing JSON `site_settings` record; announcement duration is stored as an existing absolute UTC `ends_at` value.

## Implemented changes / end-user acceptance

### Owner-controlled homepage statistics footer
- New optional `message` field under the existing Owner Member Statistics Admin panel; max 160 characters, clear button, and server-side Owner validation.
- Blank means **no footer is rendered**. There is no prefilled 'Demo' footer. Set any appropriate explanatory note; text is rendered as text, never HTML.
- Existing `custom` and `range` count modes continue displaying **Example online members** and **Example registered members** to distinguish illustrative figures from live statistics. Do not misrepresent configured counts as actual users. Live mode remains based on observed last-hour member activity.
- Existing refresh schedule of 1–30 minutes preserved.

### Announcements and Alerts
- Existing Owner create/edit/disable/delete and audience controls preserved.
- New expiration rule: **None**, **Specific date/time**, or **Duration (minutes / hours / days)**; max 365 days, with server-side validation. Duration begins at scheduled start or the original save time if no start was scheduled.
- Duration is converted ONCE to absolute timestamps on save. Page reloads and browser polling do **not** extend it.
- Form now includes safe live preview and expiration-preview text. Edited existing announcements load their saved absolute expiry.
- Public announcement API checks expiry on the server, returns expiry and revision timestamp for browser hiding and re-announcing edited notices.
- Alerts show active site announcements and personal notifications. A signed-in member can now remove **their own** personal notification from their inbox via an authenticated ID/user-scoped endpoint. This does not edit immutable audit history or other users' records. System-generated notifications are not exposed to Owner rewriting because they may represent billing/security events.
- Announcements shown in the page are also locally removed at expiry rather than staying visible for an extra polling interval. Server authorization remains authoritative.

### Instructor Authoring
- Question Bank dynamically distinguishes numeric and multiple-choice fields.
- In-form client validation rejects duplicate question IDs, missing explanations, invalid choices/answer mismatch, and bad numeric tolerance BEFORE attempting a server save. Backend remains authoritative.
- Adds read-only learner-facing question previews and draft question count (without publishing private answers).
- Existing draft/review versioning and Owner authorization preserved; this is not a replacement for complete historical-data validation.

## Access without TinyFish
In ordinary ChatGPT conversation, repository/web tools can read public pages and files but cannot simply become a signed-in user by accepting an account name/password in chat. For supported sites use **ChatGPT Work** with the built-in browser on desktop (`Ctrl+Shift+B` Windows) or Work Cloud Browser, signing in to the dedicated test account via secure browser sign-in. The model does not see the password. Availability is plan/workspace dependent. A low-privilege test account should not have Owner privileges.
