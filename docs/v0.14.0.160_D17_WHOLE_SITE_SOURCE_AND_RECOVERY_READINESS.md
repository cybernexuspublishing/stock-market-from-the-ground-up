## Source defects corrected since the first audit
- **Support credentials:** The active Support endpoint now handles modern opaque Supabase service credentials using the API key header and legacy JWT service credentials with their appropriate role header. Runtime permission checks remain reserved for D18.
- **Support input integrity:** The active Support endpoint now bounds actual JSON request bytes to 16 KB before parsing, validates ticket IDs and prevents oversized requests from reaching ticket records.
- **Support ticket ownership:** Reopening a ticket requires a prior member-owned ticket read and an eligible closed/resolved state; the update remains filtered by member ID.
- **Admin inspection:** The active `admin-unified-preview.html` uses `assets/js/admin-unified-stage-b-v014160.mjs`, replacing the broken controller. Inspect controls now correspond to the row being viewed and the separate summary view has no undefined `data` reference. The historical v014156 controller remains in the source tree but is not the active page entrypoint.
- **Source verification:** The current D17 security checker reads the active Admin script configured in HTML, not an unused archived script. Direct execution of the current source guard yielded **13/13 pass**. The dedicated member-owned Support regression is `tests/test_v014160_d17_support_authorization.mjs` and is registered in CI; its actual GitHub Actions result is not independently observed.
- **GWS, CMS, navigation, SEO and accessibility:** Current source gate also checks approved read-only/draft defaults and build-time public accessibility/SEO protections. This cannot certify full product acceptance or live tenant isolation.
