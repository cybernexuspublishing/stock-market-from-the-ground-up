## Architecturally verified issues and corrections

**1. Replay first decision.** The server previously locked the first decision through a conditional REST PATCH; existing private session rows did not independently prevent a subsequent privileged update of locked reasoning, order assumptions, session owner or cursor. A new PostgreSQL BEFORE UPDATE guard rejects revisions after decision lock and out-of-order cursor changes. Existing v95 forward RPC remains the only supported bar-advance authority. Published OHLCV data remain under the existing v95 immutability guard.

**2. Link and outcome.** v118 supersedes the v94/v115 installer for new projects or replaces the SAME RPC in place on an existing approved project. Finalization still atomically records one first-decision snapshot, member-owned Journal link and finished server session. Retries remain idempotent. A new Journal guard allows learner reflections but forbids changed first-decision identity, financial outcomes, status, grades or ordinary deletion of linked educational evidence. Genuine broker trades must be recorded separately, not pasted into fictitious replay results.

**3. Review scheduling.** v115 set ENTER replay Journal status `planned`, but v0.7 automatically creates 1D/7D/30D review tasks only for `no_trade` and `closed`. v118 schedules all three existing `journal_reviews` stages in the same finalization transaction, using ON CONFLICT preservation. WATCH and OBSERVE no longer automatically receive the misleading NO_TRADE status: only explicit NO_TRADE is that status. This improves consistency without changing prior linked records in place.

**4. Outcome-hidden study sequence.** Earlier review notes lived only in a browser textarea until after the outcome was visible, so a learner could rewrite their claimed first impression. The existing Journal review queue now uses the private v118 transaction: `lock` immutable pre-reveal notes (20–3000 chars), `reveal` then permits later comparison, `complete` atomically saves post-reveal notes and the existing `journal_reviews` completion. Only due stages can be completed. The complementary table stores this *review state*, not market bars, grade tables or another Journal. Both direct unaudited member writes and a second attempt to rewrite the initial impression are blocked.

**5. Member access, privacy, and no-lookahead.** Cloudflare checks actual Market Simulator or Historical Replay tool entitlement on every review API action and SQL crosschecks the verified member ID with the existing link. Members cannot download private future bars, another member's replay session, another member's note, or service-role secrets. Reviews use already finished, permitted Journal observations, and no browser signal becomes authenticated historical price evidence.

**6. Official 30 competencies.** The existing `competency_evidence` records, reviewed rubric requirements, four distinct dimensions and the 30 canonical competency definitions are unchanged. The Skills API and page show owner-scoped counts of replay-linked sessions and completed spaced review stages strictly labeled `ungraded`. NO recognition/decision/process/knowledge score, grade, mastery, trade P&L, or Lab pass is invented from a replay completion. Separately reviewed rubrics remain the only legitimate bridge for assessed knowledge as previously approved.

## Deployment — ONE replay lifecycle SQL

**Existing project:** `supabase/migrations/v0.14.0.118_REPLAY_LIFECYCLE_OWNER_REVIEW_REQUIRED.sql`. This single file reuses existing v94/v115 link table/RPC and adds the v118 guards/review state. On an installation without v94/v115, review and run v118 **instead of** both older installers, but only after v92, v95 and Journal dependencies have been established. On an installation already using v115, this script updates the same function without deleting prior links or notes. Do not run v94 or v115 AFTER v118.

**Prior to live enablement:** run the v94 read-only dependency preflight and `supabase/admin/v0.14.0.118_REPLAY_LIFECYCLE_POSTFLIGHT_READ_ONLY.sql` after install; verify table policies, private RPC grants and five trigger states, rights-approved published dataset(s), zero mismatched links or false financial results, all three review stages and chronology. A SQL Editor “Success. No rows returned” indicates successful execution, not production member acceptance.

**Existing Cloudflare flag:** `GU_REPLAY_JOURNAL_V01494_ENABLED=true` only *after* SQL installation and isolation/authorization checks. Do not create extra Cloudflare projects or credentials. If the flag is already enabled, coordinate rollout to avoid a live function-schema mismatch.

## CI and live acceptance distinction

The new CI workflow applies the **actual v118 owner SQL** to a disposable PostgreSQL 16 schema. It tests server user-scope, rights revocation, idempotent Journal links, first-decision protection, no fabricated trades/competency score, scheduled 1D/7D/30D reviews, due gates, immutable outcome-hidden notes, completion ordering and authenticated direct-write rejection. Node tests validate the existing API/browser contract and source build, not live Cloudflare login or real RLS across installed policies.

**Manual production acceptance outstanding:** authenticated two-member isolation with real deployed roles, environment variable values, re-login/resume and token-rotation behavior, revoked rights, actual database rollback under competing requests, service-role permissions, screen reader and keyboard navigation, pre/post reveal reload states, user data privacy/retention handling, exact verified source license and scholarly review of individual 419 Labs. These are the remaining Owner-controlled or observational checks, not “99% proven”.
