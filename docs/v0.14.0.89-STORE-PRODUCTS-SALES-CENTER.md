## Owner's controlling requirements

The Store is a **commercial storefront**: customers must see a price, clear availability, a meaningful primary action, and a product page explaining what is received. All future offerings must be visible **as Coming Soon** instead of disappearing. The Admin Control Center needs one **Products** management destination with exactly **Memberships**, **Books**, **À-la-Carte Tools** subcategories. No duplicate catalog or arbitrary test SKU.

## Implemented Store

1. **Memberships:** clear configured price/interval, explanatory detail link, and a primary **Choose This Membership** button when the same existing read-only payment-route and SKU readiness checks used by checkout confirm the product. Free continues to use **Get Free Access**. Other plans display **Coming Soon — enrollment not yet available**. The actual checkout page still validates user status, exact provider amount, terms, and Stripe session creation.
2. **À-la-Carte:** all live, beta, planned or paused active/public Supabase tool records, not just live four. LIVE verified tool offers show the price prominently and **Subscribe Now**; no unchecked external payment link. Unready entries show **Coming Soon**, with a descriptive page and no buy button. Additional **existing** website capabilities (guided historical labs, skill assessment, independently authorized historical replay training, learning progress, optional data connections) are visible as explicitly *non-sellable future offerings*: pricing not announced; links point only to existing first-party information pages. They are **not invented Stripe products**.
3. **Books:** present authorized Amazon/direct-format purchase links when configured; otherwise clearly **Coming Soon — Book purchase links pending**, rather than asserting that a sale-ready flag itself authorizes an order. The CTA now says **Explore Book & Purchase Options**. All titles/KDP/covers/manuscript content remain unchanged until the Owner chooses to edit in Products.
4. **Customer copy:** generic internal phrase “Subject areas and learning focus (not a chapter list)” replaced with the buyer-facing **“What you’ll learn in this book”**. Original curriculum bullet meaning has not been edited.

## Unified Owner/Admin Products

- **Admin → Products → Memberships:** real plan rows with price and interval, Owner-editable name and customer-facing catalog description, public and checkout state. The existing **Owner-only, audited visibility RPC** supports public listing/selection control and one-way pausing of new checkout without canceling current subscribers. **No generic enabling** of Stripe LIVE or new plan prices.
- **Admin → Products → Books:** existing full catalog editor relocated, keeping saved records and KDP Select exclusivity rules. Adds visibility, sale status, cover image, and sample link controls; preserves stored metadata and existing edition links when fields are omitted. Uses existing RBAC `catalog.manage`.
- **Admin → Products → À-la-Carte Tools:** lists all current/unreleased rows, current prices/status, links and the existing `tools.manage` editor. Future records default to planned and without a verified paid Stripe checkout. A server-side safety update refuses live price changes, activating new LIVE offerings, modifying independently linked checkout destinations, expanding active entitlements/free previews, or abruptly pausing a billed LIVE tool in the generic editor. Those require a coordinated approval/Stripe product+price+fulfillment process.

An older Members & Tools panel remains internally mounted for legacy dependencies but is hidden in canonical navigation to avoid duplicate management surfaces. Existing Orders/Subscriptions in Commerce and user-specific entitlements in Account Management remain where they belong.

## Hard boundaries and known gaps

**Do not claim all product edits are enabled.** This release consolidates safe content/availability management, but **does not** let a generic browser editor rewrite a Stripe price/product mapping, subscription contract, already-paid access, legal/KDP rights, or current LIVE entitlement matrix. Pricing changes require a new verified Stripe price + provider mapping and contract communication; tool launches require sales/entitlement/readiness acceptance. These are future controlled workflows, not silently editable numbers.

Membership names and ordinary customer descriptions can now be edited in Products by an authenticated OWNER using a revision-checked, separately audited backend action. Contractual included/excluded benefit statements remain version-controlled editorial content; altering contractual benefits, price, billing interval, Stripe mapping, or active grants still requires a coordinated legal/payment/entitlement rollout. Book Amazon URLs must be supplied and checked by Owner; no Amazon purchase link is invented. Physical direct fulfillment remains separately gated. No customer funds are spent in testing.

**Operational risks:** read-only SKU readiness calls are additional network requests (parallel, short timeout, and fail-closed); offer quote may change between page load and payment, so final checkout verifies again. The Owner-facing Products area depends on current permissions `catalog.view`, `commerce.view`, `catalog.manage`, `tools.manage`, and an existing Owner plan-control endpoint; there is no secret token or service role in the browser. Product and payment data are not copied into a duplicate database.

Unauthorized admins cannot change Owner-only plan availability or live Stripe prices.
5. Test negative writes: attempted LIVE tool reprice, retired paid tool, unverified release, changed checkout URL and changed entitlement flags are blocked by the API (not just by UI).
6. Verify CI/production browser acceptance and manual keyboard/mobile audit; **real paid order fulfillment is not certified by read-only GETs**.
