## What the member sees

1. A labeled, multi-line question field with a 450-character limit, Ctrl/Command+Enter submit shortcut and mobile-friendly action button.
2. Explain concept, guided self-check, ungraded reasoning review, and personalized study-priority modes. Review mode requires the member to type a response; no answer keys or private rubric are submitted to AI.
3. A chronological, accessible on-page conversation: their exact question, optional submitted reasoning, course response, source descriptions, disclosure of generative versus deterministic content, and a follow-up input.
4. Current-view clear, copy response, JSON export, delete individual saved exchanges, delete all server-saved exchanges, and refresh saved notes.
5. Explicit explanation when signed out, not entitled, or private storage unavailable. No fabricated scores, approval or model usage.

## Preserved services

**Tutor engine:** `POST /api/market-tutor-v01492` remains the single server-owned teaching endpoint. Its current public glossary/reference and original concept guides remain the only built-in instructional sources. Paid generative responses remain OFF unless the Owner separately approves provider budget, configures `AI_TUTOR_API_KEY`, `AI_TUTOR_MODEL`, `AI_TUTOR_PAID_GENERATION_ENABLED=true`, and installs the existing atomic usage-quota SQL. There is no implied ChatGPT-powered generation simply because the product is named Market Tutor. The UI labels each response transparently.

**Existing entitlement:** `toolAccess(...,'MARKET_TUTOR')` is reused. A subscriber without Tutor access gets a clear restricted message, not an unauthorized fallback disguised as AI.

**New optional history API:** `GET|POST|DELETE /api/member-tutor-history-v014102`. Authenticates the user on each call. Uses the same member entitlement check, server-side Supabase service key, parameterized user-scoped REST filters, stringent length/UUID/mode checks, rate-bounded retention of 200 exchanges per member, idempotent request IDs, and an explicit mass-delete confirmation header. The stored content is a **member-saved ungraded educational note**, not a trustworthy immutable AI log or grading artifact (the browser can submit its own notes).

**Source protection:** no private Lab answer keys, journal bodies, private financial data, unpublished candles, client API keys or secrets are included in the new history endpoints. User content and assistant output render only with `textContent`; no third-party tracking or browser `localStorage` persistence of learner responses. JSON export is intentionally local to the member's browser.

### Recommended tests

- Signed-in eligible member: submit question, submit written review, view chronology, ask follow-up, reload with and without installed history SQL, delete one and all, export personal notes.
- Unauthenticated: static public glossary only, no private history.
- Free/non-entitled/suspended: server denial; no implicit anonymous downgrade to paid teaching.
- Failure case: expired token, network offline, missing history schema, duplicate POST, two concurrent tabs, 200-record limit, client XSS text, delayed response.
- Accessibility: labels, status announcements, keyboard-only Ctrl/Command+Enter and focus transitions, phone widths and screen reader log.
- Optional AI: ensure no paid API requests when disabled or quota RPC absent. When enabled in future, verify pricing controls, provider policy, citations and user consent separately.
