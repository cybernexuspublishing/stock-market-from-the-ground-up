## What the member sees

1. A labeled, multi-line question field with a 450-character limit, Ctrl/Command+Enter submit shortcut and mobile-friendly action button.
2. Explain concept, guided self-check, ungraded reasoning review, and personalized study-priority modes. Review mode requires the member to type a response; no answer keys or private rubric are submitted to AI.
3. A chronological, accessible on-page conversation: their exact question, optional submitted reasoning, course response, source descriptions, disclosure of generative versus deterministic content, and a follow-up input. External generative AI requires a separate per-request unchecked-by-default consent box; optional account-history saving has its own member-controlled checkbox.
4. Current-view clear, copy response, JSON export, delete individual saved exchanges, delete all server-saved exchanges, and refresh saved notes.
5. Explicit explanation when signed out, not entitled, or private storage unavailable. No fabricated scores, approval or model usage.

## Preserved services

**Tutor engine:** `POST /api/market-tutor-v01492` remains the single server-owned teaching endpoint. Its current public glossary/reference and original concept guides remain the only built-in instructional sources. Paid generative responses remain OFF unless the Owner separately approves provider budget, configures `AI_TUTOR_API_KEY`, `AI_TUTOR_MODEL`, `AI_SERVICE_ENABLED=true`, `AI_SERVICE_MEMBER_DAILY_LIMIT`, `AI_SERVICE_GLOBAL_DAILY_LIMIT`, `AI_SERVICE_GLOBAL_MONTHLY_LIMIT`, and installs the v0.14.0.103 atomic usage-quota SQL. `AI_TUTOR_PAID_GENERATION_ENABLED` is an obsolete flag and does not activate paid inference. There is no implied ChatGPT-powered generation simply because the product is named Market Tutor. The UI labels each response transparently.

**Existing entitlement:** `toolAccess(...,'MARKET_TUTOR')` is reused. A subscriber without Tutor access gets a clear restricted message, not an unauthorized fallback disguised as AI.

**New optional history API:** `GET|POST|DELETE /api/member-tutor-history-v014102`. Authenticates the user on each call. Uses the same member entitlement check, server-side Supabase service key, parameterized user-scoped REST filters, stringent length/UUID/mode checks, storage bounded to 200 exchanges per member, idempotent request IDs, and an explicit mass-delete confirmation header. **Updated in v0.14.0.107:** The browser can no longer upload a claimed Tutor answer. The authenticated Tutor endpoint saves its own generated response to existing v102 storage with a `verified:` provenance prefix. Older user-saved copies remain labeled legacy/unverified; server provenance is not cryptographic attestation, grading or market-history verification.

**Source protection:** no private Lab answer keys, journal bodies, private financial data, unpublished candles, client API keys or secrets are included in the new history endpoints. User content and assistant output render only with `textContent`; no third-party tracking or browser `localStorage` persistence of learner responses. JSON export is intentionally local to the member's browser.

## Privacy and production acceptance

Unresolved: approve the member-transcript retention period, administrative/legal data request/erasure procedures, provider disclosures for future generative features, abuse and spam rate limiting at the edge, and cross-browser accessibility tests. Existing entitlement expiration restricts access to saved Tutor notes; a future account-data export path independent of active paid entitlement should be evaluated before public launch. The SQL stores notes in the provider's managed database; do not claim audited cryptographic end-to-end encryption.

### Recommended tests

- Signed-in eligible member: opt in/out of optional model use and private transcript storage; submit question, submit written review, view chronology, ask follow-up, reload with and without installed history SQL, delete one and all, export personal notes.
- Unauthenticated: static public glossary only, no private history.
- Free/non-entitled/suspended: server denial; no implicit anonymous downgrade to paid teaching.
- Failure case: expired token, network offline, missing history schema, duplicate POST, two concurrent tabs, 200-record limit, client XSS text, delayed response.
- Accessibility: labels, status announcements, keyboard-only Ctrl/Command+Enter and focus transitions, phone widths and screen reader log.
- Optional AI: ensure no paid API requests without explicit per-question member opt-in, when disabled, or when quota RPC absent. When enabled in future, verify pricing controls, provider policy, citations and user consent separately.
