## Source of truth and no-change boundaries

1. `public.platform_plans`: price, term, active/public visibility and plan checkout availability. UI does **not** hard-code sellability; live payments continue to pass through `checkout.html` to signed GU58 LIVE checkout.
2. `public.platform_tools`: status, positive individual monthly price, public visibility and supported link. Only **released / live**, priced tools appear in the À-la-Carte sale tab. Beta/planned tools remain under Tool Roadmap, not represented as purchasable.
3. `public.catalog_products` (with existing `data/store-products.json` fallback): all **book** records and publication status; registered Amazon format URLs; author, publisher, descriptions, format-level checkout flags. A `sales_status='published'` label is NOT payment activation. No changed book metadata, Amazon listing, KDP Select flag, manuscript, artwork or download entitlement. An Owner may still need to correct the preexisting website KDP Select flags; this release deliberately leaves them untouched.
4. `data/store-product-guides-v01484.json`: separate educational context and marketing boundaries for five supported membership codes, four paid individual tools, and five current books. For books the learning-focus list is a **subject-area preview**, not a claim about chapter-level manuscript contents or publication clearance. Owner must review these summaries against final books before treating them as editorially approved. Updating this file does NOT change the publishing catalog.
5. **No browser makes a Stripe API call or a Supabase grant.** A paid plan or individual tool links only to the existing protected checkout route. The 0-dollar LIVE test remains absent and closed. A missing live catalog disables any new paid purchase proposal instead of substituting stale prices.

## Information architecture

- `store.html#memberships`: Free, Full Monthly, Full Annual, Lifetime, and independently billed OnDemand Monthly when public/active, **plus a separate coming-soon preview of the planned Replay training membership** (not a payable product). Includes complete feature comparison and live tool-name links.
- `store.html#books`: only actual book records, their previously configured cover, description, author, publication labels, book-family subfilters and enabled format-purchase channels.
- `store.html#tools`: only released/live independently priced tools; each has a detail link; no beta, planned or future tools are sold by implication.
- Every visible product headline and image (where present) leads to a **distinct, stable HTML route** with shared verified data rendering. Future, unregistered SKU codes can have their own deep links under `store-product.html?type=...&code=...` but are **nonpurchasable** until present in the backend's active catalog and provider readiness checks pass.

## Cross-functional acceptance and identified risks

| Discipline | Requirement, specific finding or limitation |
|---|---|
| Product/UX | Exactly one Store category visible; no misplaced tool in memberships or bundled non-book in Books; all purchasable cards have obvious detailed product page links. |
| Accessibility | Semantic tablist/tab/tabpanel; aria-selected/controls, Home/End and arrow keyboard support; responsive size >=44px; focus-visible; feature table scoped row/column headings and keyboard-scrollable container. Manual screen reader/zoom acceptance still required. |
| E-commerce | Price/term/status from current DB, not local education text; secure checkout verifies again server-side; book purchase buttons appear only when independently enabled for each format. No premature "Buy" button for a book merely labeled sale-ready. |
| Auth/security | All dynamic UI text escaped; external and file URLs allowlisted; no Store-side service key or direct payment mutation; no changes to roles, JWT, RLS, signed webhooks, forum moderation or access grants. |
| Stocks/trading domain | Tool claims are bounded to historical practice, market reasoning, risk, liquidity and documented trade process. No earnings guarantee, personalized advice, implied brokerage or licensed market-data inclusion. |
| Book accuracy | Existing KDP URLs/metadata remain untouched under Owner control. Individual learning-focus previews are **not verified against manuscripts** and must be editorially reviewed before final commercial launch. |
| Contract consistency | **Outstanding discrepancy:** Current membership marketing describes limited Monthly sponsorship, minimal Annual sponsorship and ad-free Lifetime; an older membership module/database seed uses `ad_free=true` for both paid Full plans. Audit actual advertising enforcement and approved sales terms before resolving these claims; no flag changed here. |
| Subscription entitlement | Full Monthly/Annual companion learning must not be confused with `includes_all_books` used for downloadable book distribution. These are different rights and should be verified in production against access resolver and published policy. |
| Forum/sitewide | User's universal engineering standard applies to forum and all other modules; this PR deliberately makes **no claim** that forum privacy, moderation, reports, spam, policy enforcement or accessibility received new testing. Forum requires separate acceptance to close any sitewide audit. |
| Deployment | HTML/JS/CSS are Cloudflare Pages static assets. Service worker is network-first for HTML/assets; reload and inspect after deployment. No new Cloudflare flags or Supabase SQL required for Store tabs or detail pages. |
