**Project:** The Stock Market: From the Ground Up + private Grant Web Solutions drafts.

**Date:** 2026-10-13 | **Status:** Source-tested, **not** deployed or production-approved.  
**Purpose:** Close demonstrated Owner-account-status guard holes, reconcile release labels, establish ordered master backlog.  
**Dependencies:** Existing Supabase profile, admin_user_roles, admin_user_flags and v0.14.0.0 plan/GWS contracts.

### Confirmed source defects fixed

1. `functions/api/plan-controls.js`: was validating OWNER role and account kind but **not** user suspension/restriction state; a still-signed-in suspended OWNER could have listed plans or called mutation RPC. Now checks `admin_user_flags.status` server-side on both methods.
2. `functions/api/gws-projects.js`: same condition permitted access to private GWS customer drafts for a suspended/restricted OWNER. The Owner check now includes the account restriction status, rejecting the request before private draft query or mutation.
3. `config.js`, `docs/CURRENT_RELEASE.md` and SW controller/cache used older release markers after version advancement. Corrected active labels to v0.14.0.5 (historical archive docs remain historical).

**The new guards preserve the existing OWNER role, account-kind and optional MFA requirements.** The account restriction verification uses the same `admin_user_flags` table queried by existing v0.14.0.4 paid-tool and checkout guards. Accounts with no flags row retain earlier semantics, pending an explicit default-deny policy review.

### Owner upload procedure

1. Save the existing GitHub `main` SHA or create a protected rollback tag; do not delete/recreate GitHub, Cloudflare, or Supabase.
2. Unzip **v0.14.0.5** at the **root** of the existing local GitHub checkout, overwriting matching stable-named files. Avoid uploading the ZIP itself or nesting an extra folder. Existing historical SQL/API compatibility file names remain untouched.
3. Run `node tests/v0145_owner_status_guard.mjs`, `node tests/v0144_route_contracts.mjs`, and `bash scripts/build-pages.sh` from the repository root. Review the checksums/changes in `docs/v0.14.0.5_FILE_MANIFEST.csv`.
4. Commit on a review branch and push manually. Keep Cloudflare Pages build command `bash scripts/build-pages.sh`, output `public`, production branch `main`.
5. Preview-test with safe expendable accounts: active OWNER plan list and GWS drafts authorized; restricted/suspended OWNER denied on GET and POST; normal member, TEST, SHOWCASE denied. Avoid production destructive checks.
6. Merge to `main` only after preview acceptance. Verify actual deployed build/asset marker and review Pages Functions errors.
7. Roll back by reverting the GitHub commit and redeploying previous known-good code. No SQL rollback needed; preserve existing Supabase data and encryption secrets.
