## Per-item Owner controls
Admin Control Center -> Products -> **All Store Items**.
- Search by SKU, title, or category.
- Open an item to edit its customer-facing name, description, Store status and display visibility.
- Save just that SKU; an optimistic `version` guard rejects stale browser edits.
- Owner can create new **draft-only** Boot Camp/clinic, add-on and supporting-feature Store items. They begin Coming Soon, visible, unpriced and unable to sell.
- New membership, book or tool products use the existing domain editors. New book/tool rows automatically receive Coming Soon Store faces.
- Price labels in this registry are read-only customer display hints, **not** canonical provider prices. No Owner input can set a charge amount or Stripe Price ID through these controls.

**Statuses:** `in_development`, `coming_soon`, `ready_for_review`, `listed`, `for_sale`, `paused`.

`listed` means a product face is visible and the customer should open the original reviewed product page for actual purchase eligibility. It is NOT a financial claim. `for_sale` is blocked at DB CHECK constraint and Owner API until the independent `sale_ready` flag is set by a separate verified release. On migration installation, **0/60** were sale-ready and **0/60** were flagged for sale. Existing external retailer and protected eight-SKU checkout systems were not modified.

## Existing product authority
- `platform_plans`, `platform_tools`, `catalog_products`: master product terms and access.
- `gu_storefront_items_v014174`: public face, visibility and editorial status only.
- Stripe mode-specific Product+Price: provider catalog and billing cadence; account-specific mappings.
- Cloudflare Checkout + DB route: server-verified sales eligibility and idempotent fulfillment.
- Historical lessons, copyrighted books, private answers and member entitlements: NOT stored in the public Store registry.

## Security and safety requirements
- New table has RLS enabled with no customer policies and all `anon` / `authenticated` table privileges revoked. Only server service-role can read or edit.
- Public API `/api/storefront-catalog-v014174` returns only visible, nonsecret display fields, with `Cache-Control: no-store` and fail-closed unavailable response.
- Owner edit requires valid user authentication, `control_panel.access`, `catalog.manage`, and OWNER role; Showcase cannot modify items.
- SQL check `status != 'for_sale' OR sale_ready=true`. Service Admin editor cannot write `sale_ready`, price, internal routing, or entitlements.
- Owner update is compared against expected version; concurrent saves with stale versions fail.
- Neither the public listing nor the Owner item-edit endpoint links straight to Stripe or accepts a price or customer identity.
- Deleting/archiving source domain products does not revoke already purchased entitlements. Book rights, personal data and payment ledgers remain independent.
