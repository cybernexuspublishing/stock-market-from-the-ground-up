# v0.14.0.13 — Source, Directory, Integration and Publishing-Boundary Audit

**Source package audited:** v0.14.0.12, 509 files. **GitHub inspected:** `cybernexuspublishing/stock-market-from-the-ground-up`, branch `main`, commit `5fe5ec216335fb1bfc88a16d271e88c98063e974`, 492 tracked files (October 14, 2026 UTC).

**Finding: the published repository is NOT an exact match for the ZIP.** The previous release's static syntax/reference checks were insufficient to detect repository leftovers and omitted migration source files. File enumeration plus syntax checks cannot prove every operational dependency or Supabase permission works in production.

## Confirmed critical finding: outdated authored training data remains tracked on GitHub

- `data/interactive-labs.json` is tracked on GitHub `main` (blob SHA `dd6c5b628908008e8b56635e26d462f75d156eb8`). **The v0.14.0.12 release ZIP does not contain it.** Extracting a ZIP over an existing Git checkout does not delete a tracked leftover.
- The previous Pages builder copied the *entire* `data/` directory to `public/`, which could publish the authored data when that stale tracked file remains on disk. Public deployment exposure was **not independently confirmed** by the browser tool.
- This release makes the build **fail closed** if that private authored file is present, and copies only twelve explicitly approved public `data/` files. `.gitignore` excludes re-adding the private data once untracked. The private content was NOT copied into this ZIP.
- **Owner action required:** If `data/interactive-labs.json` exists in the local Git checkout, make a private backup **outside the GitHub repository** if needed; then remove it from Git tracking (`git rm -- data/interactive-labs.json` or remove the file using GitHub Desktop) and commit/push the deletion. The ignore entry does *not* untrack an existing file. Confirm the file is absent from `main` and the Pages deployment; consider repository history exposure separately. Keep private answer keys in restricted Supabase storage. Never put private keys in the source repository.
- **Do not deploy v0.14.0.13 until that tracked file is removed.** The build guard is intentionally blocking until it is gone.

## Deployment guidance

1. Keep the known-good git commit/Cloudflare rollback point and a private backup of authored source outside Git.
2. Remove Git-tracked `data/interactive-labs.json` from the existing working checkout and GitHub main (after private backup as required); verify deletion is committed. This is **not** achieved by extracting the ZIP alone.
3. Extract the complete v0.14.0.13 ZIP into the existing checkout; verify 18 SQL sources will be committed without re-executing them in Supabase.
4. Run `python scripts/check-connectivity.py` and `bash scripts/build-pages.sh` locally or on Cloudflare preview. The build intentionally fails if the stale private file survives.
5. Verify file is absent from build output and public URL; use a preview deployment and conduct auth/Admin/Forums/member tests before production.
6. **No new SQL migration is introduced by this source audit.** Never run SQL B automatically. Owner retains manual deployment control.
