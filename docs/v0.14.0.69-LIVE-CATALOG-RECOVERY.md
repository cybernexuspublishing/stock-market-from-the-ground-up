## Source remediation

Previously, `stripe-live-merchant-readiness-v01467.js` fetched the mapped Product **before** its Price and caught all GET errors under the indistinguishable status `UNVERIFIED`. A 404 Product response prevented reading a perfectly valid LIVE Price and its real Product association.

As of this release, the Owner-only review instead:
1. Fetches configured **LIVE Price first** and reports missing Price (404) separately from restricted key (403), invalid key (401), transport failures and price-contract mismatches. A matching Price that belongs to a different Product reports `PRODUCT_ID_MISMATCH` and the LIVE Product ID from the returned Price object. The Price and Product must both be verified before marking a SKU PASS.
2. If the mapped eight are not all verified, invokes the existing LIVE account's read-only `GET /v1/prices` listing with expanded Product object, paginated to a bounded maximum of 500 prices. It only suggests pairings when an actual active LIVE Price meets the exact approved USD fixed amount, recurrence and licensed billing plus the exact normalized *known* product name (or approved name alias).
3. Reports per-SKU `EXACT_LIVE_CANDIDATE`, `NO_EXACT_LIVE_MATCH`, `AMBIGUOUS_MULTIPLE_PRICES`, or `DATABASE_NOT_VERIFIED`. A **copy-ready proposed eight-pair JSON** appears only when all eight matches are individually unique, have eight distinct Product and Price IDs, and the provider list was completely paginated. This is a proposal for Owner verification, **not** live approval or an applied Cloudflare setting.
4. Includes a manual-copy UI in Admin → Commerce → Payments & Billing → **Run LIVE Merchant Review — No Charge**, visible only to an authenticated Owner with recent password confirmation. The UI renders provider IDs as text and does not insert secrets, customer data, or webhooks into its response.

Neither the application nor the assistant creates a new Stripe Product/Price; it does not rotate secrets, update Cloudflare bindings, write to Supabase, create a Checkout Session, send a signed event, or change Owner mode/fulfillment approval. Existing GU58 checkout continues to accept exactly eight plan/tool SKUs with its own independent live price verification. The KDP Select, signed printed-book, Lulu and digital book rights/payment channels remain separate.

## Correct next acceptance

After Cloudflare deploy, the Owner runs the same existing no-charge Admin report **once**. The output should now identify:
- `NOT_FOUND_IN_LIVE_ACCOUNT`: that configured Price does not exist in authenticated LIVE Stripe account. Recover exact corresponding LIVE Price and Product pair from the complete proposal or Stripe LIVE dashboard.
- `PRODUCT_ID_MISMATCH`: mapped Price exists in LIVE but its Product ID differs. Confirm and correct paired ID in Cloudflare.
- `READ_PERMISSION_DENIED`: authenticated API key lacks the required Price/List read permission; configure a permitted secret only after Owner review.
- `AMBIGUOUS_MULTIPLE_PRICES`: overlapping live fixed Price candidates; choose intended approved offer manually, never guess.

If a complete, unambiguous candidate map is offered, the Owner may review each mapping and paste the JSON directly into Cloudflare encrypted server-side `GU58_STRIPE_LIVE_CATALOG_JSON` in the **same existing production Pages project**. No automatic application is allowed. If some candidates are missing, the Owner must review those specific LIVE products/prices rather than recreate all eight blindly.

The Owner previously confirmed Stripe products remain visible, but existence in the Dashboard alone does not prove Price IDs match active LIVE Price objects in the authenticated account. Platform membership fulfillment, installed GU58 SQL definition parity, legal terms/tax, actual signed-event lifecycle and final explicit LIVE authorization still require independent acceptance.
