## Explicit security and launch restrictions
1. LIVE flags are **not configured** or enabled as part of this release. The present production Owner mode can stay TESTING, and customer checkout stays blocked. Do **not** add `sk_live_` keys to GitHub, client config, chat messages or documentation.
2. Proposed `GU58_LIVE_CHECKOUT_ENABLED=true` requires separate `GU58_LIVE_FULFILLMENT_APPROVED=true`, `GU58_LIVE_DB_CONTRACT_APPROVED=true`, `GU_PAYMENT_LIVE_LAUNCH_APPROVED=true`, the Owner TEST switch OFF, the confirmed LIVE merchant account ID, live `sk_live_` secret, webhook signing secret, complete `GU58_STRIPE_LIVE_CATALOG_JSON` and validated DB / visible checkout gates.
3. `GU58_LIVE_WEBHOOK_ENABLED` is separately authorized. It is **not automatically disabled when TESTING is selected** if past live subscriptions exist; otherwise renewals, cancellations, disputes and refunds could go unreconciled. Existing customers must have a safe ongoing webhook path even when sales are closed.
4. `GU58_STRIPE_LIVE_CATALOG_JSON` consists of all eight approved `sku: {product_id,price_id}` pairs in the **LIVE account**. Test catalog IDs are invalid. Account ID and amounts must be checked against the live account and approved site catalog.
5. Webhook lifecycle handling, subscription cancel-at-period-end, latest-invoice refund boundaries, duplicate/out-of-order provider events and tax/coupon policy require provider and database integration acceptance, not just code tests.
6. The v58 database migration contains financial mutations. It is **REVIEW REQUIRED** and is not to be executed without a database backup, SQL contract check, qualified review and Owner authorization. Until installed, all attempts fail closed.
7. The offered pricing, KDP Select rights, digital book downloads, tax positions, and separate physical-book channels are **not reopened**. Stripe merchant "Action required" banner observed in sandbox is not evidence that the LIVE account is blocked.
