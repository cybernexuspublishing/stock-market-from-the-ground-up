# Admin Authorization Revocation and Legacy Panel Compatibility — v0.14.0.253–254

Date: 2026-10-25 · Branch: `main` · Scope: existing administrative API authorization, owner diagnostics and database request compatibility only.

## Implemented security changes
1. The main Admin endpoint now rechecks the staff profile and moderation flag after validating its current role grants. Restricted, suspended, deleted, and test profiles do not retain privileged access just because a previously issued session token remains valid. Showcase roles cannot be mixed with production roles.
2. Unified Account Management independently checks the same conditions before reading or changing private account records. Synthetic Showcase remains separate and read-only, with only a valid `SHOWCASE_VIEWER` role/profile combination.
3. The read-only Owner Pre-LIVE Acceptance endpoint rejects deleted, restricted and suspended Owners.
4. Legacy Account & Access, Owner Site Management, Operations Intelligence, and operational configuration/report endpoints now recheck live profile/flag/role status and reject mixed Owner/Showcase authority.
5. Fixed obsolete unconditional `authorization: Bearer <sb_secret_...>` on the legacy Account & Access and operational modules. Modern Supabase secrets are passed as server-side `apikey`; traditional JWT-style service keys retain their supported bearer behavior.
6. Extended the Deployment 16 Admin regression to test current and revoked sessions, test/deleted profiles, mixed roles, and all four legacy modules. No real user accounts were changed by the mocked tests.
