# v0.14.0.224 — Founding 600 Final Launch Gate (Evidence-Only Audit)

**Disposition: BLOCKED. Do not activate live founding payments.**

This release-gate memo records actual test evidence, separates simulated tests from Stripe-delivered events, and intentionally does **not** treat a source-code pass as payment-launch acceptance. The production website is built from GitHub `main`. Existing Stripe products and prices remain unchanged.

- Cloudflare Production deploy from `main`; membership enrollment, billing, and fulfillment are all **false** in `gu_founder_release_v014173`.
- No genuine founding members or paid founding cycles were created by QA.
- First paid-cycle Supabase transaction (rollback): original seat assigned, paid-cycle ledger inserted, active subscription inserted, and Standard **5** included Sparks recorded. An earlier failing SQL trigger was repaired in v0.14.0.214.

No live entitlement tables involved.
- Existing registered Stripe Sandbox endpoint `/api/gu39-stripe-webhook` received an **actual Stripe-delivered, signed** `customer.subscription.updated` event after the QA marker was added to an existing test subscription. Isolated `gu_f600_sandbox_events_v014215` recorded exactly one event and status `cancel_scheduled`. Sandbox processing gate was restored **false**.
- Stripe Sandbox verified paid $49.99 and $59.99 subscriptions in earlier acceptance; both use day-based 30/60-day cadence; cancellation-at-period-end was verified and one prior $49.99 test refund succeeded.
- Signed-HMAC, isolated Sandbox webhook source tests passed in the Founding 600 CI source gate, with no LIVE member or Sparks write capability.

This is **not** a genuine browser login using a customer account.

- LIVE lifecycle source recognizes verified cancellation scheduling, payment failure, full refund and disputes with explicit fail-closed handling. New provider-state SQL function is service-role-only, and the LIVE webhook remains disabled.
- Refund invoice discovery was corrected for Stripe's 2026 response shape where `Charge.invoice` is absent; it uses the Stripe InvoicePayment association to PaymentIntent.

## Not passed / owner testing still required

1. **A complete Stripe Sandbox Checkout-session → actual signed `invoice.paid` delivery → provider-confirmed subscription → isolated entitlement QA record**, with successful idempotent replay. Historical Sandbox subscriptions were created before the new isolated QA marker; provider-side creation of an additional marked subscription was blocked. One genuine subscription-update webhook delivery is verified, but this is not enough to certify initial payment fulfillment.
2. Provider-triggered **30- and 60-day renewals via Stripe Test Clocks**, including real signed invoice events, exactly one new allocation per successful cycle and proper included-Sparks expiration.
3. Provider-triggered failed payment, recovery and cancellation on each tier; paid-through access must not be cut off by merely setting `cancel_at_period_end`.
4. **Real signed Sandbox refund/dispute delivery** into the isolated QA ledger; a previous successful Stripe Test refund was not linked to a QA founding intent at the time it was issued. Partial refunds require manual review.
5. Separate first-party checkout policy enforcement for Lifetime Membership ($2,249.10 Standard / $1,999.20 Extended) and purchased Sparks, including Extended 20% vesting and refund reversals. The protected entitlement-calculation RPC is installed but purchase-route application is not fully verified.
6. Production authenticated-browser tests using a legitimate, non-Showcase Standard member and Extended member, including private support, original founder number, accessibility, screen readers, keyboard focus, checkout success/failure surfaces, and credentials that are subsequently revoked.
7. Latest combined GitHub Actions SOURCE workflow run must complete successfully **after** all LIVE webhook/refund updates and browser tests. A previously green run does not automatically certify later commits.
8. Final human security/operational sign-off and explicit approval before LIVE Stripe account keys, payment endpoint and founder fulfillment switches may be activated.

## Permanent safety controls

- LIVE checkout, LIVE billing, LIVE webhook and founding fulfillment must remain disabled until every final gate is satisfied.
- Never use actual auth member identities, `site_subscriptions`, `gu_founder_members_v014173`, or real `groundup_question_pass_buckets` to store Sandbox test cycles.
- Turn the shared GU39 Sandbox mode OFF after each isolated QA run.
- Never mark Stripe Test Mode events as `livemode=true`; never use LIVE Stripe keys or webhook secrets for Sandbox acceptance.
- All original founding numbers remain nonrecyclable once genuinely issued.
