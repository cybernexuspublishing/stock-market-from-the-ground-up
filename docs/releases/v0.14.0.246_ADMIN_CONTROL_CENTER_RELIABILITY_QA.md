# Admin Control Center reliability gate — v0.14.0.246

**Scope:** existing Owner/Admin interface reliability before real payment acceptance.

## Included
- Refresh Supabase access tokens on each request for the core, v11 and legacy Admin API clients. Do not cache the access token for the lifetime of an open administrative page.
- Await every core panel loader so rejected API responses are captured; show one accessible error with a functional Retry section button. Clear older errors before retrying.
- Restrict core navigation listeners to elements owned by the core navigation controller. Independent modules retain their own click behavior.
- Add Node 22 regression and syntax checks to the existing Deployment 16 Admin acceptance workflow.

## Explicit exclusions
- No Stripe LIVE charge, checkout activation, new product price, membership grant, advertising activation, identity change, or payment secret modification.
- Existing Showcase stays isolated and read-only; new code does not modify server authorization or privileged database tables.
- Source tests are not a substitute for authenticated Owner browser acceptance. Report the workflow and deployment state separately before marking production accepted.

## Acceptance conditions
1. Two consecutive core Admin API calls use two freshly requested sessions, never one cached bearer.
2. Rejected async responses yield an accessible visible error with an operable Retry section control.
3. Repeated failures do not stack duplicate error panels.
4. Existing additional Admin module tab handlers are unaffected by the core tab bootstrap.
5. GitHub Actions regression executes successfully, Pages production reaches success, and authenticated Owner QA confirms behavior without touching LIVE payments.
