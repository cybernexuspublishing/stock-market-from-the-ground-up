Cloudflare Owner Admin creates an **authenticated, server-verified** Checkout Session in Stripe TEST mode only; each session is bound to a uniquely identified Supabase QA order *before* returning a Checkout URL. The URL is checked to use `https://checkout.stripe.com`. Users never receive API keys, service role secrets or webhook signing secrets.

The existing Stripe TEST endpoint `/api/gu39-stripe-webhook` verifies the unaltered Stripe event body with its HMAC signature and checks the known TEST merchant account and independent database Test Mode. Only tagged advertising events are routed into the new isolated `gu_ad_sandbox_intents_v014240` and `gu_ad_sandbox_events_v014240` tables, using a service-role-only atomic ledger RPC. Events for unrelated test transactions retain their pre-existing handler.

The webhook subscription includes `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`, `charge.refunded`, and `charge.dispute.created`.

A paid event requires exact `100` cents, correct TEST Price and Product, matching Checkout metadata and previously bound session, and a re-fetched succeeded TEST PaymentIntent with exactly `100` cents received. Duplicated event IDs are acknowledged without duplicating the QA receipt. Full refunds/disputes mark the QA order reversed. Partial refunds remain manual review. No real advertising package is sold; ad campaigns and commercial payment records remain untouched.

## Owner test procedure (no real money)

1. Sign in with your genuine Owner account at `/admin-advertising.html`. Do not use a Showcase account.
2. Under **Stripe Sandbox — Advertising Payment Acceptance**, choose **Enable advertising Sandbox**. This toggles both dedicated ad QA and the existing sitewide Stripe TEST gate; LIVE customer checkout is intentionally blocked while test mode is ON. The three commercial ad package prices stay unset.
3. For **Site Sponsorship**, click **Open Stripe TEST Checkout**, then use the verified Checkout link shown after the server binds the order.
4. Complete checkout with a **Stripe test card** using Stripe's published [test payment methods](https://docs.stripe.com/testing). **Never use a real card.** This produces a $1.00 TEST-only charge, not a real bank charge.
5. Return to the Owner Admin and press **Refresh Sandbox results**. Verify the order reaches **paid** with one signed TEST webhook event and recorded test amount `$1.00`. This is an isolated QA receipt, not ad delivery.
6. Repeat for **Section Sponsorship** and **Educational Resource Sponsorship**. Check no `ad_campaigns`, `gu_ad_order_evidence_v014226`, `site_subscriptions`, or member entitlement record was generated.
7. In the **Stripe TEST Dashboard**, refund one test charge in full. Refresh the Owner Admin: only its QA order should transition to **refunded**. Test a declined card and an abandoned session to check failure/expiry when practical; use the TEST environment only.
8. Select **Disable advertising Sandbox and restore site payment mode**. Verify `gu_ad_sandbox_settings_v014240.testing_enabled=false` and `gu39_sandbox_settings.enabled=false`.
9. Confirm LIVE advertising `accepting_payments=false` and `ad_delivery_enabled=false`, with no active commercial campaigns.
