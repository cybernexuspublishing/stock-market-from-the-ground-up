# Admin RBAC integrity — v0.14.0.252

Date: October 25, 2026. Branch: main. Scope: non-LIVE Admin security and Admin navigation reliability.

## Implemented
1. Created an atomic, `SECURITY INVOKER`, service-role-only PostgreSQL RPC for the Admin role-permission matrix. It validates the actual Owner account, profile type, current restrictions, absence of Showcase role, target role, permission catalog, and an optimistic-concurrency snapshot. A role row lock serializes updates. Permission changes and the Admin audit entry occur in the same transaction.
2. Preserved the deliberately separate Owner-account creation and transfer workflows, while prohibiting editing the `OWNER` and `SHOWCASE_VIEWER` permission matrices through the generic role editor.
3. Restricted permission editing and generic role-definition edits to a current OWNER. Non-Owner staff may read authorized roles and permissions.
4. Updated the Admin navigation registry to use Supabase modern `sb_secret_` keys as `apikey`, without creating a `Bearer sb_secret_` header. Rejected mixed Showcase/Owner roles.
5. Added a Node 22 runtime regression for role authorization, immutable protected roles, optimistic concurrency, and Admin navigation secret key support. Included it in the existing Deployment 16 Admin workflow.
6. Committed the same applied SQL function to versioned Supabase migrations for reproducibility.

## Database acceptance
The migration applied successfully. A controlled SQL BEGIN/ROLLBACK validated the atomic modification and restoration of MODERATOR permissions, stale-edit rejection, unknown-code rejection and immutable OWNER protections. Explicit database grants checked: `service_role` EXECUTE yes; `authenticated` no; `anon` no. All trial mutations were rolled back.
