## Implemented engineering corrections

1. **Zero-ambiguity Tutor HTTP boundary.** Shared request parser checks same-origin `Origin` and Fetch Metadata, JSON Content-Type, body byte limit, proper data types, approved mode and question/response bounds, UUID request ID, and explicit boolean consent. Parsing occurs *before* authentication-based Tutor rate/budget reservations; invalid attempts cannot consume a member's source or paid requests. Browser-supplied prior turns remain untrusted and discarded.
2. **Verified member note identity and idempotency.** The existing private v102 RPC now receives the member's per-question UUID instead of a fresh random UUID for each write. After RPC success, the server reads back the exact user-scoped saved answer/mode/question/generation before claiming `historySaved`. A replayed UUID with changed text cannot be misreported as the newly saved response. This does not make educational content factual or independently evaluated.
3. **History security.** Both PATCH feedback and DELETE operations reject cross-origin and cross-site requests. The v102 older-column fallback is used only for verified missing v107 feedback columns, not arbitrary RLS, storage, or network errors. 200-record bound, entitlement checks and server-only role key are preserved.
4. **Account change / concurrency.** Signed-out and re-signed-in browser sessions carry a generation counter to invalidate stale Tutor responses, history loads and AI status refreshes, including a return to the same user UUID.
5. **Provider failure truthfulness.** Known incomplete or errored Responses results are rejected before cited answers can be accepted. Unverified semantic citation quality remains a human/editorial release gate; model access is not enabled by this deployment.
6. **Owner review.** Stable, unversioned `GET /api/owner-tutor-feedback` verifies Auth and active OWNER role, denies test/showcase/suspended identities, and returns only bounded reported feedback metadata. Existing Admin Control Center → Content & Tutor receives a read-only Owner report panel. No member UUID, transcript body, question, answer, private rubric or credentials are returned. A report is an allegation, not a verified defect; resolution requires a future audited workflow.
7. **Read-only installed-contract diagnostic.** `supabase/admin/v0.14.0.147_TUTOR_EXISTING_CONTRACT_READ_ONLY.sql` inspects the existing v102/v103/v107 schema and RLS privilege evidence, without executing or re-running migrations.

## Known blockers and explicit scope boundaries

- A working Owner report inbox is **read-only**. Audit-consistent report assignment, resolution, appeal, retention and notification are NOT implemented in this deployment.
- Current history access requires an active Market Tutor entitlement; export and account-data portability after expiry require a privacy-law review and independent safe account-data flow.
- Existing zero-cost source request throttling depends on optional v107 SQL installation. If unavailable, v103 paid model quota still blocks spending beyond configured limits; full abuse prevention is not certified.
- The current model citation check remains structural, not proof every claim is entailed by the cited training source. A trained instructor must review the 12 golden cases and a broader diverse pedagogical evaluation before claiming instructional quality.
- The live AI provider is not assumed configured or funded; no production provider call, vendor privacy contract, data-processing agreement, actual API spend cap or invoice has been verified.
- Existing `member-tool-access.js` entitlement checks and SHOWCASE/TEST role policy require independent real-user production validation; tests of these endpoints do not prove systemwide authorization.
- Cloudflare Pages success does not establish actual production-member browser correctness. Verify Owner vs Member vs TEST/Showcase, session switching, actual storage RLS and simultaneous-tab idempotency separately.
- No real historical trade data or unapproved books/curriculum copied. No service keys in public static assets, documents or logs.
