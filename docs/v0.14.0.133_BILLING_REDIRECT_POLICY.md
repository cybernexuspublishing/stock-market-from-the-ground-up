## Production evidence

The owner-provided October 21, 2026 03:48:11Z invocation for Worker version `26457562-6189-40ea-8ddc-621c433b4a35` reports `BILLING_RECONCILIATION_FETCH_FAILURE` with `TypeError:REDIRECT_REJECTED` and a scheduled invocation error for `*/1 * * * *`. The error originated while the Worker called `POST /api/internal-billing-reconcile` with `redirect:'error'`. This strongly indicates a redirect was encountered before a reconciliation HTTP result was delivered, **but the log does not contain the HTTP redirect status or destination**. A separate external GET to both APIs returned HTTP 405; this does not verify POST or Worker-origin routing.

The deployed every-minute Cron is **not** the approved production schedule. The source-controlled Wrangler config specifies **only** `0 12 * * *` (daily at 12:00 UTC). Do not keep or recreate `*/1 * * * *`.

## Implementation

Switch only the scheduled outgoing `fetch()` request from `redirect:'error'` to `redirect:'manual'`. On a 3xx response, log `BILLING_RECONCILIATION_REDIRECT_BLOCKED` with numeric status and one fixed destination class: `LOCATION_MISSING`, `INVALID_LOCATION`, `INSECURE_DESTINATION`, `CROSS_ORIGIN`, `SAME_ORIGIN_OTHER_PATH` or `SAME_ORIGIN_SAME_PATH`. Throw a fixed error so the scheduled invocation still fails visibly.

No redirect is ever followed, including same-origin redirects. Do not log the Location header, the original URL, raw exception, authorization secret or Stripe/Supabase/member data. Reconciliation success requires a direct HTTP 200 with the existing verified counts.

Do **not** fix by switching to `redirect:'follow'`; Cloudflare warns that it forwards authorization headers across domains.
