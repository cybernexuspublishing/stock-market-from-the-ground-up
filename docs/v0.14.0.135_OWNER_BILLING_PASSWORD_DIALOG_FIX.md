## Verified defect and root cause

The Owner reported that **LIVE Billing Reconciliation — Private Evidence** returned "Reconfirm the Owner password before accessing private billing evidence" but no dialog opened.

Review of v134 `assets/js/admin-billing-reconciliation.js` confirms a client-side integration defect: a raw `fetch('/api/billing-reconciliation-health')` surfaced `PASSWORD_RECONFIRM_REQUIRED` as plain text without calling the existing `window.GroundUpAdminPasswordConfirm.ensure()`. That component is loaded by `assets/js/site.js` on Admin pages and already provides the existing password + configured Cloudflare Turnstile experience for other Owner operations. Its RPC interception does not intercept a raw Cloudflare Pages fetch. The v134 endpoint itself intentionally enforces Owner+password step-up and must not be weakened.

## Source correction

- On **exactly HTTP 403 with `PASSWORD_RECONFIRM_REQUIRED`**, invoke the **existing** password + Turnstile dialog. Do not create another authentication system or prompt for a password in the billing UI.
- On confirmed dialog success, issue **at most one** fresh authorized read-only GET to the existing unversioned endpoint.
- On cancellation, absent shared component, repeated 403, 401, or any other failure, show an actionable non-sensitive message and **do not** retry recursively or reveal financial records.
- Preserve server-side Owner/session/password verification, no-store semantics, and all billing/Stripe/SQL security.
- Add cache-busting `?v=014135` to existing browser script reference; no versioned API route.
- Add Chromium browser regression with mocked endpoints and simulated Turnstile to verify dialog appears, one retry, cancellation, ongoing rejection, non-Owner rejection and missing module behavior. Tests do not submit actual passwords or call real Stripe/Supabase.

## Owner production acceptance

After GitHub CI passes and the existing Cloudflare Pages production deployment finishes, open the website Admin (consider a hard refresh to replace browser-cached v134 assets), then Commerce → LIVE Billing Reconciliation — Private Evidence → Review Billing Reconciliation — No Charge.

Expected: if password confirmation is required, a modal labeled **Confirm your password** opens. Complete the configured Turnstile verification and enter the Owner account password **only within the website's own dialog**. The modal closes after successful confirmation and the read-only evidence request automatically retries once. If verification is not configured, the modal should explain required configuration, without allowing an unverified password submission. If canceled, it closes and no second evidence request is made.

**Evidence needed:** The displayed report or its safe error code, with no credentials, member identities or Stripe identifiers included. API HTTP 401/403 tests alone do not prove the Owner browser modal is functioning.
