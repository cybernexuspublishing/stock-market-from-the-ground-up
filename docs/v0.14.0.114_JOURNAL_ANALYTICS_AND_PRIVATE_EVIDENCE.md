## Verified architectural issue

The original `journal-analytics.js` used browser-side `SiteAccess.isMember` as the paid analytics check and read every accessible `decision_journal` row into browser memory to compute results. A client-computed feature gate cannot secure a paid feature; journal RLS is intended to support legitimate Free journaling and cannot substitute paid analytics authorization. In addition, `Number(null)>0` can misrepresent missing net results and the original win rate denominator included incomplete outcomes. CSV exports contained spreadsheet-formula injection risk for member-entered fields.

## Changes

**Private paid API:** `GET /api/journal-analytics-v014114?type=all|live|paper&days=all|30|90|365`. Requires a current validated Supabase bearer session, active eligible member flags and backend `user_has_tool_access` for `JOURNAL_ANALYTICS`. It reads only that user’s completed live/paper journal records with a narrow projection, inside the existing Supabase project; returns only aggregate values. A second member cannot select someone else’s user ID. This API has no mutation route and uses `private,no-store`. It rejects unsupported filters and fails instead of silently truncating more than 3,000 private rows.

**Financial definitions:** Closed trades count toward results only if net P&L is finite and explicitly entered; null, empty, no-trade and open records do not become losses, wins or flat outcomes. Win rate counts profitable trade records divided by resolved eligible trades, including genuine flat results in the denominator. Profit factor is gross profit divided by absolute gross loss and is **undefined** (not infinite or 100%) when no recorded losses exist. Expectancy is the net P&L mean across resolved trades; average R uses only entries with actual R measurements (denominator displayed). Drawdown is the maximum absolute peak-to-trough decline of cumulative self-reported net trade outcomes, starting at zero. No account-balance return percentages or actual broker equity are inferred without starting capital and cash-flow history.

**Learning-quality integration:** Outcome/process matrix, documented plan adherence, bad-process winners, setup groups, entry/exit reasons, session and mistake frequencies, planned-versus-actual exit categories, MFE/MAE and MFE capture aggregates, and live vs paper transfer review are retained using server-calculated aggregates. Small sample (<20) notices warn the learner of estimate instability. Values are **self-reported**, not externally authenticated historical evidence or independent official competency scores.

**User experience:** `journal-analytics.html` now renders accessible status text, setup comparison tables, cumulative net result SVG with descriptive title and tabular summary, sample-quality disclosure, process/error groups, and MFE/MAE review from paid protected server results. The browser no longer reads the raw private journal rows to compute paid metrics. Session changes hide the account report and prevent stale fetch responses from replacing current member data.

**Privacy/security:** Personal journal narratives and trading-plan text do not enter the paid analytics API response; no prompt-like data is logged. `journal-common.js` now prefixes spreadsheet formula-like member input on CSV export, including leading whitespace before =, +, -, or @, so journal CSV exports cannot trivially execute `HYPERLINK` or arbitrary spreadsheet formulas.

**Owner Roadmap:** Adds a truthful Journal Analytics source-implementation gate and updates `CORE-0221`. The 21-tool product inventory, four existing paid tool SKUs, prices, manually saved Owner progress, and audited SQL statuses are preserved.
