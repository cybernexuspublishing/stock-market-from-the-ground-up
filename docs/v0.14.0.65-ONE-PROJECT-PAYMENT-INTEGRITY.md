## Confirmed source risk and corrective action

The prior LIVE Stripe Price verification checked `currency=usd`, `unit_amount`, Product ID and the label `recurring.interval=month/year`, but **did not check `recurring.interval_count`, `recurring.usage_type`, or `billing_scheme`**. An otherwise matching Price could consequently describe a multi-month billing interval or metered/tiered pricing inconsistent with the approved fixed recurring offer.

`functions/api/stripe-live-checkout-v01458.js` now requires for every recurring plan/tool:
- The exact requested recurring interval with **`interval_count=1`**.
- **`usage_type=licensed`**, not metered usage.
- **`billing_scheme=per_unit`** and no quantity transformation.
- The existing exact product, LIVE flag, active status, USD currency, and fixed cent amount checks.

One-time Lifetime checkout retains its separate one-time price requirement and additionally requires fixed per-unit pricing. Missing price attributes fail closed. No approved SKU, price amount, catalog entry, membership, user, merchant secret, or checkout flag changed. Stripe's Price API returns these fields on the retrieved Price object; see Stripe API documentation: https://docs.stripe.com/api/prices/object .

## No-charge provider and Supabase acceptance

**New file:** `supabase/admin/v0.14.0.65_ONE_PROJECT_PAYMENT_READINESS_READ_ONLY.sql`

Use this single script in the SQL Editor of the **existing Supabase project only**, at the eventual Owner handoff. It returns one grid for export and does not modify any record. It covers:

1. The existing GU39 Owner TEST selector state, without presenting OFF as LIVE approval.
2. Unbound prepared TEST intents that may require reconciliation in Stripe TEST logs, without creating a second checkout.
3. Presence and structural eligibility of all eight canonical SKUs, with current database prices; database prices are **not** independent Stripe LIVE Price approval.
4. Installed (or missing) GU58 live ledger and event RPC components and high-value RLS/permission checks.
5. Explicit external-acceptance and Owner LIVE-authority `NOT_APPROVED` rows, because SQL cannot verify Cloudflare credentials, real Stripe LIVE products, merchant eligibility, tax, customer terms, or webhook delivery.

A `PASS` or `PRESENT` from SQL is **not evidence of a completed external Stripe charge**, entitlement grant, provider webhook, or authorization to change Cloudflare settings. A missing GU58 migration is reported without installing it. Never execute the review-required GU58 migration merely because the report indicates it is absent.
