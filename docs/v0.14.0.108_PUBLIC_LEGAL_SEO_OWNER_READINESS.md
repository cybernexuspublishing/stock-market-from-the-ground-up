## Defects identified and repaired

1. **Legal page visibility to search engines.** The site's existing `privacy.html`, `terms.html`, `refund-policy.html`, `cookie-policy.html` and `subscription-terms.html` shells rely entirely on client-side queries to `legal_documents`. The shared Cloudflare Pages middleware now retrieves only the **published and effective** version from the existing Supabase table, using the public publishable key and existing RLS (not a service-role key), renders a deliberately limited/escaped Markdown subset into the existing page before delivering HTML, and updates the document title. The browser loader checks `data-policy-server-rendered=true` to avoid replacing server-rendered content. If the database is unavailable, the original client fallback remains; no replacement policy is invented. Public SSR lookup timeout: 1.8 seconds.
2. **Missing root robots and sitemap.** Added `GET /robots.txt` and `GET /sitemap.xml` native Cloudflare Pages routes. The sitemap includes a limited verified set of public core pages and only legal document paths whose published records have current effective dates. No draft policies, private user routes, staff interfaces, future Lab answer keys, data connections or individual profile content are surfaced. Production host comes from the incoming URL; `*.pages.dev` preview robots disallow crawling and the sitemap returns a noindex 404. This does NOT replace authoritative account access checks.
3. **Broken modern Supabase key usage in the old managed-page sitemap.** Prior code unconditionally sent `authorization: Bearer sb_secret_*`, which is invalid for opaque service keys. It now uses `apikey`, adding bearer authorization only for legacy JWT-style service role keys. This is a compatibility fix to the existing separate `/managed-pages-sitemap.xml` route, not evidence that Page Builder is installed.
4. **No favicon and no icon entry.** Added a lightweight SVG mark consistent with existing site colors, linked sitewide through existing HTML head middleware and referenced in `manifest.webmanifest`. It is a provisional functional icon; owner-specific artwork was not reconstructed or replaced. **Standalone PWA installability remains unverified**, and browsers can require 192x192 / 512x512 PNG masks; do not claim the SVG alone closes this launch gate.
5. **Unknown production legal records.** Added an Owner-only `GET /api/owner-roadmap?action=legal-publication-audit` with the same verified Owner role as the existing roadmap. It reports state/version for five key required policy codes and warns for missing/draft/future/short records; it never sends full unpublished bodies to browsers. The Owner Product Development tab exposes a Refresh button and clear compliance-not-certified labels. Publishing a database record does NOT confirm legal sufficiency, AI provider disclosures, cookie consent, refunds, data erasure or accessibility.

## Operational boundaries

- No new Supabase SQL, Cloudflare secrets, Stripe products or book manuscript changes for this source phase.
- Public sitemap routes use the current hostname only. Configure actual canonical hostname redirects and verify production URLs using real browser/SEO tools; neither the preview nor a GitHub Actions mock is a Google/Bing crawl test.
- LEGAL: require qualified review of current `legal_documents` content, including privacy/AI provider request processing, location of data, sharing, payments/refunds, cookies, consumer rights and retention. Many seeded pages are concise summaries and may not satisfy applicable law.
- SECURITY: existing CSP remains partly report-only; eliminating `unsafe-inline` is an independent refactor. Robots directives never secure private URLs.
- RELIABILITY: Supabase/RLS may be slow or unavailable; the legal SSR helper times out and degrades to existing client rendering. Do not market legal page availability as guaranteed until acceptance.
- OPERATIONAL: backups, restore drills, uptime monitoring, staff incident access, forum audit atomicity, 419 lesson-by-lesson acceptance and true licensed market history remain distinct gates in the Owner Roadmap.
