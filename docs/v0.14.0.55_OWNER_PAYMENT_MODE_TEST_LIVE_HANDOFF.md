## Owner request and non-negotiable invariant

One prominent, accessible, sliding **LIVE ↔ TESTING** control in **Admin Control Center → Payments & Billing → Stripe Payment Testing**.

**TESTING selected:** temporarily block every known server-created *customer* checkout endpoint, protect real members/entitlements, and allow only the existing isolated test payment routes after their own authorization, Cloudflare secret/TEST-gate and provider conditions pass.

**LIVE selected:** disable new isolated TEST checkout. Restore the normal customer checkout path **only if the Owner has separately approved and implemented production commerce**, with an independent server-side launch flag plus all existing provider/plan/book controls. Merely sliding the toggle to LIVE must *never* activate real charges for a launch that has not been accepted.

TESTING/LIVE are mutually exclusive in the existing Supabase row `gu39_sandbox_settings.enabled`. A single Owner role + recent-password/Turnstile-confirmed existing DB RPC `gu39_sandbox_owner_toggle` records the switch, version-timestamps it and writes the admin audit log. No schema modification and no new test payments are made by the toggle itself.

## Design and security implementation

- An accessible native checkbox with `role=switch`, 2 text labels LIVE and TESTING, distinct visual states, keyboard operation, contrast, visible focus and reduced-motion support.
- The page is only a controller: the Cloudflare API determines the actual state from Supabase, never from a browser localStorage flag.
- Client sends the existing, Owner-protected `{action:'toggle',enabled,updatedAt}` request; password + manual human verification are preserved. The interface reverts the slider if confirmation fails.
- The **Cloudflare global middleware** checks that same database row, fresh, on each new checkout creation request. When TESTING, it denies customer checkout requests before any provider session or new order/intent write; also rejects live provider quote requests.
- Routes covered: `/api/checkout`, `/api/checkout-v0135`, `/api/stripe-customer-checkout-v01438`, `/api/signed-book-checkout`. Legacy `/api/stripe-managed-sandbox-v01432r2` is permitted only when TESTING selected; its separate TEST infrastructure/flags remain mandatory.
- The v39 GU39 Stripe TEST route already independently enforces the Owner DB switch and Cloudflare TEST secret gate. This release retains its existing 9/9 pre-payment audit and blocked unresolved intent requirement.
- LIVE checkout requires **GU_PAYMENT_LIVE_LAUNCH_APPROVED=true** in Cloudflare **Production** as an *independent* release-authorization flag, plus every relevant route's existing provider and Owner checkout switches. This flag remains absent/false: production checkout not ready or approved. No changes to real Stripe/Lemon accounts or provider price catalog.
- If the mode state cannot be read, any monitored new LIVE/legacy TEST checkout is denied with `PAYMENT_MODE_UNAVAILABLE`. Real-time checkout states are never assumed from an old cached setting.
- Webhook endpoints are deliberately **not blocked** by mode switching: they may need to process existing paid invoices, refunds or subscription events. Switching modes does **not** automatically cancel previously created hosted checkout sessions, ongoing subscriptions or in-flight provider transactions.
- This new mode barrier does not retroactively invalidate third-party payment links already published outside these API routes. Physical payments/direct links/other apps must have separate provider controls; no claim of universal control without integration audit.
- Never use this slider to enable real customer checkout until Merchant of Record / Stripe Managed Payments eligibility and full payment lifecycle have separate Owner acceptance.
