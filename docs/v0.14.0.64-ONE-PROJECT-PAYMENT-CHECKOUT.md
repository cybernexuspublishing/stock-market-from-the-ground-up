## Implemented
1. Customer checkout had a dead-end dependency on `/api/stripe-customer-checkout-v01438` (requires a second Supabase project, and refused the existing production ref). The browser now uses the existing `/api/stripe-live-checkout-v01458` **only** after a new per-SKU, read-only availability probe passes. No second provider adapter or database is introduced.
2. Availability rechecks the approved Owner launch flags, whether LIVE checkout and signed-event webhook handling are both enabled, canonical eight SKU map, Owner TEST/LIVE switch OFF, relevant plan/tool release and per-offer gates, website-wide checkout gate, Stripe merchant account and actual LIVE price/product/currency/interval/amount. Any unavailable service returns `liveCheckoutAvailable:false`. The actual POST rechecks all conditions; its session creation is still separately guarded by `functions/_middleware.js`.
3. Corrected an important omission: the LIVE Checkout server may no longer create a chargeable Checkout Session when its matching LIVE webhook handler is switched OFF. Previously the checkout code could accept other launch flags while `GU58_LIVE_WEBHOOK_ENABLED=false`.
4. KDP book and bundle purchases continue to use their separate publishing-rights and fulfillment gates. GU39 Owner-only TEST Stripe checkout and shadow ledger remain unchanged; no test purchase activates a real account.
5. New CI acceptance `tests/test_v014064_checkout_wiring.mjs` executes the actual per-SKU LIVE GET handler against mocked provider/database and asserts no new sessions, price changes, subscriptions or entitlements were created.
