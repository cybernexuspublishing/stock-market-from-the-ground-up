## Specific security problem corrected in source

The original `assets/js/advanced-tools.js` authorized 16 beta tools with browser-computed `my_platform_access` and `free_preview`, then wrote private records directly using an authenticated Supabase session. The original `tool_workspace_records` policy only enforced owner ID matching, not paid entitlement. This allowed an authenticated Free account to bypass the browser paywall and store/read beta tool records via direct database requests.

### New backend / member path

1. All 16 canonical beta code paths invoke `GET /api/advanced-tool-access-v014110?tool=<CODE>`, using the member's bearer session. Server checks real Supabase user, account kind, account flags, Showcase/test exclusion, active beta/live product catalog, entitlement via existing `user_has_tool_access`, and optional explicitly enabled public Free Preview. The retired/planned Options Lab is not included.
2. Beta workbench saved records go through `/api/advanced-tool-workspace-v014110`. The server validates the member and current tool access on **every request**, scopes all record queries/deletions to the authenticated user ID AND tool code, checks actual UTF-8 payload bytes, rejects cross-origin modifications and validates record types.
3. Member interface provides read, save, paginated JSON export (up to 10,100 rows using pages of 100, fail instead of silent truncation), delete one and explicitly confirmed delete all for this tool. Records never award grades, trading outcomes or historical-data certification.
4. Generic tool page shows an educational trading/no-real-data disclaimer.
5. The existing 21-tool Owner Product Development inventory remains intact. All 16 beta tool gates were updated to reflect that **source** is implemented but real DB permission lockdown/entitlement QA is pending. Planning percentages stay unchanged. Owner's saved statuses are preserved.

### Remaining architectural constraints

- **Browser calculations are still inspectable**. A backend gate can prevent access through the canonical application and saved data but cannot make shipped JavaScript algorithms confidential or truly subscription-enforced. Move paid-only computation, scarce feeds and privileged datasets behind functions as each tool clears its product-specific acceptance.
- Retain the unified platform tool registry, existing memberships, plan grants, trial rules, and four paid Stripe tool SKUs. Do not create duplicate prices or a second payments/catalog system.
- Historical replay datasets are not verified; simulator browser candle data/fills are still distinct from the locked server replay engine. Do not mark real-market performance, official historical OHLCV or no-lookahead simulation approved.
- No license verification, math correctness, simulator fill tests, public PWA installation, real browser screen-reader acceptance, paid provider inference or genuine webhook fulfillment was performed in this source change.
- Workspace exports and deletes cover `tool_workspace_records` for a single beta tool; Journal, Tutor history, purchase invoices and other datasets have separate privacy/export processes. Overall retention policy remains unapproved.
- Server endpoint logs should record only allowlisted reason codes, never prompts, saved research, private quotes, credentials or buyer details. Further IP abuse controls and aggregated observability are separate follow-up work.
