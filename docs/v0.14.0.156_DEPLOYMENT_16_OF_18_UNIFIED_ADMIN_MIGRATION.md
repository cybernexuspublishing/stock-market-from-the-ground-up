## Verified starting architecture
`admin.html` loads many scripts that independently mount navigation or panels, including `admin.js`, `admin-platform.js`, `admin-legacy-routing.js`, `admin-navigation.js`, `admin-workflows.js` and related commerce/operations modules. Blindly removing these would risk losing current Owner Account Management, educational, Stripe, moderation and audit workflows.

## Implemented in Stage A
- `assets/js/admin-unified-core-v014156.mjs`: one original six-group declarative registry with unique stable module IDs, explicit server permission mapping, fail-closed route resolution, read-only allowlisted Admin actions, fresh session access token on each request, no unconditional mutation retries, and fixed record bounds.
- `assets/js/admin-unified-preview-v014156.mjs`: separate read-only Admin shell with one active route and sidebar, stale-request cancellation, no polling/MutationObserver, DOM text-safe records, keyboard buttons, refresh control, live status, and links back to existing approved edit functions.
- `admin-unified-preview.html` and isolated CSS: accessible responsive preview. Existing `admin.html` provides a shortcut but retains all historic modules and commercial controls.
- Shared staff route policy now explicitly classifies `/admin-unified-preview.html` as **protected**, preventing it being silently treated as a public-preview route by shared Cloudflare/Service Worker classification.
- `tests/test_v014156_admin_shell.mjs` verifies exact six groups, unique registry, unauthorized-route denial, no backend writes, fresh tokens, HTML XSS-safe DOM construction and staff route classification. Dedicated CI `.github/workflows/deployment16-admin-shell.yml`.
- No new database tables or migrations. No pricing changes or production flag changes.

## Additional source repair — modern Supabase administrative key compatibility
- The inherited `functions/api/admin.js` used to submit any `SUPABASE_SECRET_KEY` as both `apikey` and Bearer token, even when the key begins with `sb_secret_`. The same defect existed in `functions/api/admin-accounts-v01353.js`.
- Both now use **API key only** for modern `sb_secret_` and **API key + Bearer** for an actual well-formed legacy JWT service key, matching the pre-existing LIVE payment middleware contract. Unknown shapes fail closed.
- Added `tests/test_v014156_admin_service_key_compatibility.mjs` and wired existing Owner account regressions into the D16 workflow. Real production Supabase account operations and exact HEAD CI results remain unverified.
