## Owner-reported defect

The authenticated Payments & Billing → Stripe Payment Testing screenshot displayed the historic button pair **Refresh Testing Status** and **Verify All 8 Sandbox Products**, immediately followed by **Enable Testing**; the new **Run Payment Test Preflight** button introduced in v0.14.0.51 was absent. Owner has not clicked the new preflight; absence is a rendering/deployment/cache defect, not evidence Stripe readiness failed.

## Confirmed source bug

In committed v0.14.0.51:
- the current JavaScript file `assets/js/admin-stripe-shadow-v01439.js` **contained** the new Preflight button and version `0.14.0.51`;
- however `admin.html` continued requesting that file as `.../admin-stripe-shadow-v01439.js?v=014047`. The URL still identified the old v0.14.0.47 asset through multiple releases.
- Cloudflare build / GitHub CI could pass while a browser, CDN, or prior service worker delivered the older bundle for that unchanged URL. The screenshots are consistent with the old JS running, though a specific network-cache response has not yet been captured.

## v0.14.0.52 correction

- Changes actual Admin HTML URL to `/assets/js/admin-stripe-shadow-v01439.js?v=014052`.
- Aligns `application-version` meta, browser SITE_CONFIG, owner roadmap, commerce config, service-worker versioned public cache and release manifest to v0.14.0.52.
- Adds an **on-screen version label** within Stripe Payment Testing: `Payment testing interface v0.14.0.52 · includes Run Payment Test Preflight`. This establishes which UI bundle rendered, not whether backend Stripe preflight passed.
- Adds CI regression asserting release number equals the Admin HTML script cache-busting parameter, button construction/mounting and the on-screen label. Existing Playwright smoke test now asserts button present.
- Leaves all eight existing Stripe TEST products and prices untouched, no database migrations, no Cloudflare environment modifications, no changes to real entitlements, live checkout OFF.
