**Scope:** Existing Admin Products extension and the 38 planned products listed in the v0.14.0.174 unified catalog. Existing 13 book/membership/tool entries retain their existing editors and payment contracts.

The non-destructive Supabase migration `v014175_owner_store_product_overlays` was installed in existing project `oxihglyfgzywsupnyicb` and returned success. Does not edit product prices, subscription rows, payment credentials, entitlements, membership statuses, or book delivery settings.

## Owner authoring contract
- Owner signs in through existing Supabase Auth. Admin API requires `control_panel.access`, `catalog.view` and active `OWNER` role.
- Canonical SKU allowlist prevents creating arbitrary preview SKUs and prevents writing an existing separately governed product via the overlay.
- Owner may save title, description, store visibility, and noncommercial editorial lifecycle (`draft`, `coming_soon`, `paused`, `release_ready`).
- Optimistic concurrency: first save expects version 0 and can insert once. Updates require matching integer version. A stale save fails rather than overwriting another editor.
- Audit row and update are one Postgres transaction. Failure of either rolls back the whole operation.
- PostgREST role validation repeated inside SQL. RLS enabled; direct anonymous/authenticated read/write and RPC execution denied.
- Public GET returns only redacted publication fields and product IDs. Hidden/draft/paused SKUs are filtered from the public Store.
- Public Store **fails closed** for upcoming product listings when availability cannot be retrieved. Existing products remain on their existing routes.
- Direct product-detail preview URLs also respect the visibility filtering. There is no checkout button or Stripe route in this feature.

## Not a payment launch
The schema excludes `for_sale`, and the RPC rejects attempted activation. A `release_ready` label is a **review planning state only** and does not grant eligibility to sell. Real sale readiness must separately confirm: price/Stripe ID and correct environment, delivery/entitlements, content/historical-data rights, assessment integrity, tax/legal conditions, refund/cancellation terms, signed-webhook and replay safety, independent account/browser QA, and explicit Owner live-payment authorization.
