## Verified defect

`functions/api/forum-member-content.js` allowed content PATCH to commit before a separate audit INSERT. An audit failure returned `auditRecorded:false` while retaining the edit/deletion. The v113 Owner/Moderator RPC correctly addressed only **moderator** actions, not **member** actions. This release closes the member gap without adding a third forum model or changing published topics' IDs.

## Changes

The existing member endpoint now invokes only `gu_v014116_member_change_with_audit`. The service-role-only, `SECURITY INVOKER` function revalidates the actual production-member/Showcase/flag status, exact author, published state, optimistic version, official Commons restrictions, and parent status/lock for replies. It holds a parent share lock (when editing a reply) and target row update lock; edits/deletes and an attribution-only audit record are inserted in one transaction. An audit failure rolls back the content change. The response reports `atomic:true,auditRecorded:true` only on confirmed success. No standalone PATCH fallback exists; until the SQL is installed, member edit/delete fails closed, while forum viewing and creation through existing handlers remain independent.

## Owner-only installation

New file `supabase/migrations/v0.14.0.116_ATOMIC_MEMBER_FORUM_EDITS_OWNER_REVIEW_REQUIRED.sql`. Review current columns/grants and install on the **existing Supabase project**. This is independent of the pending v113 moderator-action RPC; both are required for **full** audit integrity. No Cloudflare environment variable is added. Do not rerun previously installed v105, v110, or other historic SQL.
