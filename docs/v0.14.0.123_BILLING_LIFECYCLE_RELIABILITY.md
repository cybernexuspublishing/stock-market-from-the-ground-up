## Why this matters

GU58 LIVE webhook receives a signed Stripe event and updates the entitlement/subscription
ledger; previously no durable customer notice was recorded within that transaction.
Sending an email inline in the payment webhook is unsafe: provider outages would
make Stripe retry successful grant events, or cause notices to be lost. v123 adds
a **transactional private outbox** on the existing subscription/pass ledger, with
an encrypted-in-transit scheduled delivery route and bounded retries.
No actual email addresses or payment-card details are stored in outbox rows.
Records are generated only for GU58 member+SKU+subscription verified intent rows.
Legacy unrelated Stripe, Amazon and independently managed book transactions are excluded.

Supported statuses: activated, renewed (only changed paid period), payment failed,
cancellation scheduled/reversed, canceled, and access paused. The verified Stripe
webhook also recognizes invoice.payment_action_required and subscription
paused/resumed, subject to provider revalidation and existing GU58 fulfillment RPC.
The outbox **does not** create, modify or reinstate learning entitlements.

## Deployment (ONE existing Supabase project)

1. Run `supabase/admin/v0.14.0.123_BILLING_PREFLIGHT_READ_ONLY.sql`.
   Stop on a BLOCKED dependency. Do not repeat old migrations without review.
2. Install `supabase/migrations/v0.14.0.123_BILLING_OUTBOX_OWNER_REVIEW_REQUIRED.sql`.
3. Run `supabase/admin/v0.14.0.123_BILLING_POSTFLIGHT_READ_ONLY.sql`.
   All PASS confirms installed objects/permissions, not a delivered message.
4. Configure **GU_BILLING_TASK_SECRET** (long cryptographically random),
   **GU_BILLING_RESEND_API_KEY**, **GU_BILLING_FROM_EMAIL** (verified sending
   domain), and **GU_BILLING_SITE_ORIGIN** (canonical HTTPS store origin)
   only in Cloudflare Pages secrets. Confirm SPF, DKIM and DMARC.
5. Deploy a separate Cloudflare scheduled Worker using
   `workers/billing-notices-v014123.js` with the same task secret and origin,
   Cron Trigger (for example every 15 or 30 minutes). Cloudflare Pages
   Functions do not schedule themselves by adding a source file.
   Test its real scheduled execution and email provider receipt.
6. Confirm Stripe LIVE portal permits self-service cancellation, the webhook
   endpoint processes continuing subscriptions when checkout is disabled,
   and customer status/email changes flow only from signed Stripe events.

## Privacy, rollback and operator acceptance

A member cannot query the outbox or claim/ack another member's notices.
Only the authorized server runtime obtains Auth-verified recipient addresses.
Retries have one-time five-minute leases and stable provider idempotency headers.
Twelve failures move a notice to `dead` for owner investigation, not silent
success. Source checks are not production evidence; Owner must test two
distinct member accounts and a configured real provider.

**No grace-period change** is introduced. Existing paid entitlement behavior
can suspend paid access on `past_due`. Marketing and Billing Terms must
match that rule pending explicit owner approval of a safe bounded grace period.
Never promise paid access after disputed/refunded or canceled subscriptions.

**Forum and Market Commons:** their v113/v116 atomic edit/moderation and
authorization acceptance remain separate production requirements.

## Rollback

If delivery configuration is missing, the route returns 503 without claiming
any jobs. To pause delivery, disable the scheduled Worker, not the signed
Stripe webhook. Existing paid subscriptions must keep processing even if new
checkout is disabled. Do not delete existing outbox history to silence failures.
