# The Stock Market: From the Ground Up — v0.14.0.17 Integration and Security Status

## Release contents
This is an UPDATE to **unreleased** v0.14.0.17. It is a **drop-in overlay**, NOT a complete v0.14.0.16 repository. It cannot be the only material deployed to Cloudflare Pages. The owner must extract into their verified v0.14.0.16 Git checkout, retaining all preexisting files. Source tested in isolation; no current production Supabase session/Cloudflare preview was used.

### Installed without new SQL (editor)
- `assets/js/forum-composer.js` — complete replacement file with safe BBCode/HTML-source/visual editor, live previews, formatting, tables, spoilers, external image consent, mode switching and session-local opt-in autosave; trading education labels for user-supplied ticker/timeframe, evidence and risk context are non-verified text formatting only.
- `assets/css/rich-content-editor.css` — updated text editor styling.
- `assets/js/site.js` — complete replacement loader retaining the preexisting sales, KDP and public announcement settings; loads the editor and optional interaction module only for forum discussion URLs.
- `sw.js` — complete replacement, retained security/cache behavior, updated version marker.

### Requires an **additive, separately reviewed** SQL migration (community interactions)
- `assets/js/forum-interactions.js` and `assets/css/forum-interactions.css` — optional client for verified Supabase RPCs.
- `supabase/migrations/v0.14.0.17_ADVANCED_FORUM_INTERACTIONS_REVIEW_REQUIRED.sql` — candidate for polls (create/vote/results), thanks, ratings and subscriptions on original Forum and Market Commons. It creates six new private tables and nine RPC functions (plus helper functions). No direct table write grants to anonymous/authenticated; authenticated security-definer RPC uses signed user identity, authentic member account, restricted/showcase checks, paid/book/tool access from existing v0.14.0.3 helper, historical lab discussion exclusions and optimistic database concurrency on poll voting. Migration is **NOT verified on production database** and must not be represented as applied automatically.
- When the new RPCs are absent, the interaction component does not make simulated/unsafe writes. It does not grant permissions, bypass SQL B report lockdown or enable checkout.

### What the new interaction UI adds (once backend deployed and accepted)
After opening an actual discussion: create one poll by its author, submit votes, view aggregate results, thank/remove thanks for topics/replies, rate a topic, subscribe/unsubscribe, quote individual and up to five selected replies, post permalinks, search replies **currently loaded in the page**, print and email thread URL. Poll voting is final; multiple selections depend on poll settings. Polls on historical Lab discussions are blocked to protect no-look-ahead exercises.

**Subscription-related reply notifications are NOT sent by this release.** Storing subscription choices is not a notification delivery worker. Ratings and thanks do NOT cause member alerts until dedicated backends and preferences exist. These distinctions must be visible in acceptance tests.

### Not installed: avoid inaccurate parity claims
Full uploaded attachments/private image media, drag/drop/paste uploads, attachment malware/quarantine and quotas, topic prefixes/tag/icon persistence, member edit revisions/diff, server-side revision retention and audit guarantees, multi-layout thread rendering, moderation appeals, profile/reputation/post-count persistence, per-thread full-text search beyond visible replies, mention delivery, subscribed reply notifications, poll voters shown publicly, automated publishing schedules for member threads, payments/broker execution. No arbitrary HTML/javascript execution is allowed. The complete row-by-row parity review is `docs/v0.14.0.17_CAPABILITY_GAP_MATRIX.csv`.

## Operational caveats
- No runtime database was available for PostgreSQL parse/migration testing. Static inspection and browser-mocked RPC tests do not substitute for live verification.
- `gu_forum_polls` uses a polymorphic scope/topic ID instead of a direct FK to both legacy/Commons. A cleanup/retention plan must handle permanently purged topics.
- Full audit and appeals, poll revision/vote-retention rules, public vote identity, and notification delivery require explicitly reviewed follow-on modules.
- Private media require object-store access gating (download signatures, virus scan, quotas, ownership, retention). Do not accept arbitrary `.html`, `.svg`, executable, document macro or remote `iframe` payloads as forum attachments.
- Stock learning content needs source/timestamp provenance, non-forward-looking replay controls, information-quality markers and education-versus-investment-advice separation. The editor does not modify educational entitlement or trading execution authorization.
