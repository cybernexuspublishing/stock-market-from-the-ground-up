## Proven incident / root causes

The Owner authorized another deployment to address the known Store release QA failure `#103` and remaining Stripe checkout acceptance. On October 21 the real-production Chromium diagnostic reported **1295px document width on a 1250px viewport** for 14 product detail pages. The only actual out-of-viewport descendants were the sitewide header **`.fe-notify-button` and unread `.fe-notify-count`**, not the Store product grid, book images or sidebars. This is a global header responsiveness defect: nav + oversized search + alerts controls can exceed the page width at intermediate desktop widths, particularly when an unread announcement exists. Previous tests on PR local fixtures all passed, but production with real notice counts failed; this difference is why genuine LIVE browser diagnostics matter.

The same production Store sometimes generated **six membership cards**, while the accepted public membership set is exactly **five**: FREE, FULL_MONTHLY, FULL_ANNUAL, LIFETIME, ONDEMAND_MONTHLY. The previous filter excluded only PICK_WHAT_YOU_WANT and obvious test markers; other catalog entries could leak into public pricing and comparison. This is a catalog-policy mismatch, not permission to create a sixth Stripe LIVE SKU or invent customer access. The data source was not changed or deleted; the public Store is now restricted to five Owner-reviewed codes and disallows duplicate canonical entries by failing closed.

## Implemented changes

- In the existing global `assets/css/layout-integrity.css`, compact **only intermediate-width desktop header utilities** at 1024–1350px; preserve real keyboard-reachable Search and Alerts buttons, their established descriptive `aria-label`s, 44px touch targets and visible unread numeric badge. At 901–1023px restore numeric badge visibility omitted by the prior icon-only rule. **Do not use `overflow-x:hidden` or hide the entire global header**, because that would mask broken navigation.
- In `assets/js/store.js` centralize an allowlisted ordered `approvedPlanCatalog()` to drive **both** product cards and comparison; ignore unapproved future or QA records rather than creating unreviewed sales links. Detect duplicate canonical codes and fail closed. Do not modify database catalog entries.
- Enforce the exact-five catalog in browserless source fixtures with an injected `UNREVIEWED_REPLAY_ANNUAL` plan, and a Playwright regression using the actual canonical signed-in nav renderer and an unread notification at widths 901, 1024, 1100, 1250, 1350 and 1440px. Report controls, badge geometry and keyboard reachability.
- Retain and extend production Store `chromium-customer-acceptance` to publish precise offending bounding boxes (diagnostics, not suppressed assertions), and include **read-only LIVE production** verification during PRs for evidence before release (nonblocking until merged).

- Stripe checkout request idempotency currently prevents ordinary double-clicks in UI but does not show a database-enforced per-member/SKU in-flight reservation across devices. Design reviewed transaction isolation/migration and recovery before high-volume release, not a makeshift client-side lock.

- Independent paid stock quotes/third-party terminal licenses are not bundled or implied; all Store products remain educational tools and first-party curriculum.
