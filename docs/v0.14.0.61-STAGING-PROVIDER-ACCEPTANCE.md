## Isolation contract

This release introduces **new staging-only paths**, not customer-visible checkout buttons. Both reject requests unless the actual request host equals `GU61_STAGING_HOSTNAME` and is an explicit *preview* `<deployment>.<project>.pages.dev` hostname. The runtime Supabase URL must exactly match `GU61_STAGING_PROJECT_REF`, a 20-character project ref that is NOT the known production project. Real production Stripe keys are refused. The webhook verifies Stripe HMAC, expected TEST merchant account, TEST-mode provider objects and original bound Checkout intent before calling a service-role-only RPC. Never use a production user identity or production service-role secret in the staging environment.

The staging SQL is a controlled TEST-mode adaptation of v58's fulfillment ledger and actual subscription/plan/tool/order mutations. Names are `gu61_staging_*` and Stripe session IDs must begin with `cs_test_`. The SQL can only be applied **after review** to an independent staging Supabase database; it is NOT part of the automatic Cloudflare build. **Do not install this migration on production.** Existing production GU58 migrations, GU39 data, published prices, mode slider and KDP rights remain unchanged.
