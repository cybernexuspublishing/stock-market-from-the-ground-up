# v0.14.0.84 — Store Architecture: Product Categories and Dedicated Product Detail Pages

**Project:** The Stock Market: From the Ground Up
**Status:** Code implementation and CI regression prepared; production acceptance pending deployment.
**Date:** 2026-10-18
**Owner authority:** User retains all Cloudflare and Supabase operations; books' pre-existing KDP information is expressly owner-maintained.
**Purpose:** The main Store shows ONLY the selected category, and every catalog item has a dedicated explanation page before the customer chooses checkout.

## Files and URL architecture
- Store: `store.html` with hash categories `#memberships`, `#books`, `#a-la-carte`.
- Presentation: `assets/js/store.js` and `assets/css/store-catalog-v01484.css`.
- Fifteen individual canonical customer detail URLs: `store-product-{plan|book|tool}-{sku-code}.html`. These are independent static Cloudflare Pages paths, served without backend rewrites, with one shared vetted template/controller `assets/js/store-product-detail-v01484.js` to avoid divergent prices, purchase links and licensing terms.
- Memberships: FREE, FULL_MONTHLY, FULL_ANNUAL, LIFETIME, ONDEMAND_MONTHLY; conditional PICK_WHAT_YOU_WANT if published in the existing DB. The independent Historical Replay training preview retained under the Membership tab; price-pending enrollment remains disabled.
- Books: precisely the five existing visible catalog records (Foundations I, II, III; Day Trading Book 1; Reading the Tape), with original title, description, cover, statuses, KDP values, Amazon links and digital/physical checkout permissions UNCHANGED.
- Individual tools: all and only active/publicly visible, nonretired platform_tools (existing four paid Stripe SKUs plus any future approved entries; a future tool requires a new dedicated static page when introduced).

## Customer journey
Each category tab is keyboard-usable, supports deep-linkable URL hash and an accurate text status. Only its panel is visible; no mixing subscriptions, books or à-la-carte entries. On a product card, the product name and **View Details** route to its dedicated page. A plan page shows included, excluded, billing interval, displayed DB catalog price, linked tool scope and a link to the existing complete membership comparison. A book page identifies learning focus, the actual edition and purchase-channel status, differences between complete book files and companion content; purchase links use the existing eligible channels **only**. A tool page describes features using the DB-authored description, current lifecycle status, exclusions and separate subscription price. All pages include breadcrumbs, terms and educational risk disclosure.

## Authoritative-data and safety controls
1. The existing `CommerceTools.load()` Supabase dataset remains the source of truth for prices, flags, descriptions, product identity and public visibility. Every product detail URL has a stable code but never hard-codes a paid price or inserts a new Stripe Product/Price. Unavailable DB membership or tool data fails closed instead of showing a fabricated price.
2. Direct eBook checkout still requires the existing explicit rights gates. Book publication and KDP values are unchanged. The explanatory text does not silently convert Amazon retailer URLs into new active direct payments.
3. All plan/tool checkout links go to the **existing** `checkout.html` backend; its server must independently validate account login, auth, price, eligibility, product availability, merchant identity and signed fulfillment. The client does not promise a successful purchase merely because a detail link exists.
4. Owner-retired $0 LIVE QA is not restored. Stripe/Supabase fulfillment flags, RLS, security rules, staff authorization and protected account management remain unchanged.
5. Separate editorial learning-focus outlines on the book detail pages are summaries of the established titles and curricula, not new descriptions, claims of outcomes or edits to KDP. Before publishing edited book marketing copy, the Owner reviews exact edition manuscripts/table of contents. Trading examples remain educational and never promise returns.
6. All dynamic catalog text and URLs are escaped/validated with shared CommerceTools helpers. No HTML from user-supplied descriptions is injected as trusted code. Responsive pages use semantic headings, breadcrumb links and native link/button keyboard handling.

## Known open issues and next cross-site audit
- **Commerce mismatch:** `membership-platform.js` still displays enrollment-opening language while the Store's server-controlled checkout route may be active. Unify both only after confirming every paid GU58 checkout and entitlement/term variant; showing customer promises before backend approval is a launch risk.
- **Legacy static fallback:** `data/commerce-config.json` and `data/store-products.json` are not replacements for an accessible authoritative Supabase catalog. Free reads should continue to fail closed for priced products when DB access fails. Confirm the site's public RLS and caching strategy under load.
- **Features comparison:** The separate `membership.html` matrix uses `plan_tool_access`; each individual SKU page currently summarizes scope without a full positive/negative tool-per-plan matrix. Make the existing matrix link each tool to its detail page and reconcile feature-level entitlement exclusions with the backend.
- **Live billing/replay:** The new pages do not certify paid subscription fulfillment; actual first paid webhook, refunds, failed-payment behavior and cancellations must still be observed. No unpaid preview can grant rights.
- **Forum and all other products:** Owner requested the same standards site-wide including the forum. This Store PR does **not** claim to audit/repair forum moderation, XSS, age-gating, identity, market-content claims, financial advice warnings, copyright, rate limiting, account flags, retention or security. Conduct a separate repository-wide route/API/SQL/test threat-model audit and produce a prioritized acceptance register; do not expand the critical Store V1 deliverable without scope and regression evidence.
