### 1. Scope and control

This standard covers the 419 existing canonical Labs across Foundations, Day Trading, Reading the Tape and site-exclusive learning, and the common modules consumed by the 30-day Bootcamp wherever applicable. Exactly 30 official competencies remain unchanged. All canonical identifiers remain stable. Version 1 must not add unrelated products or rewrite book manuscripts.

### 2. Approved visual and interaction design

Use the VWAP Replay reference design throughout: consistent dark theme, compact Learning Mode dropdown, Lab identity, readable nine-stage progress, visual first, contextual explanation, observations, classification, hypothetical decisions where applicable, forecast, analysis lock, correct chronological reveal, meaningful review and results. Avoid disconnected oversized panels, excessive unrelated warnings and standalone-looking Lab pages.

### 3. Nine-stage Learning Journey

**Start → Learn → Experiment → Predict → Practice → Assess → Review → Transfer → Results**

- **Start:** objective, prerequisites, approved context and available historical setup. A setup is not proof of a verified chart.
- **Learn:** what/why/how, symbols/units, recognition, conditions, limitations, common mistakes and applicable visuals.
- **Experiment:** manipulate illustrative values and see corresponding changes in the visual and calculation; do not label fiction as history.
- **Predict:** identify available evidence and lock expected outcome/uncertainty before any authorized future reveal.
- **Practice:** new questions, chart/candle as required, relevant calculation, feedback, contextual free help and permitted retries.
- **Assess:** private, reviewed and authorized grading only; no client-side answer keys.
- **Review:** specific error diagnosis, methods, visual reading, limitations and learning corrections without violating grading disclosure policy.
- **Transfer:** materially different problem or authorized chronological replay; avoid memorized repeats.
- **Results:** distinguish completed/assisted/independent learning from official assessed competency evidence.

### 4. Modes

Support **Guided, Practice, Blind Decision and Assessment**. Mode selection is a compact accessible dropdown. Lock/restart must confirm the implications and must not erase already preserved official results. Blind and Assessment mode withhold instructional cues, private answer keys and unrevealed replay.

### 5. Subject-to-visual decision rule

A meaningful chart, diagram, table or interactive instrument must be presented at the stage where the learner must interpret the associated data. Do not insert ornamental images.

| Subject | Default visual |
|---|---|
| Single candlestick, body, OHLC, wick, body/range calculation | Labeled single candle with matching data and units |
| Pattern, structure, HH/HL/LH/LL, support/resistance, breakout, pullback, continuation, MFE/MAE | Contextual multi-candle chart with relevant levels |
| VWAP | Candles, volume and appropriate weighted-reference line; trade-group arithmetic uses matched price/volume groups |
| EMA / timeframe analysis | Price chart with appropriate moving averages and timeframe context |
| Volume and participation | Price candles plus aligned volume |
| Time & Sales / tape | Timestamped transaction-price and share-size table |
| Level II / order book / spread | Bid, ask, spread and displayed depth with market-data limitations |
| Order routing, issuance, settlement and participant relationships | Appropriate process or relationship diagram |
| Purely conceptual / non-price task | Diagram, table or written worked example only when instructional need justifies it |

**Chart provenance is separate from chart presence.** Synthetic educational OHLCV cannot be counted as approved historical evidence. The true historical exercise requires independently approved chart/data sources and observation-time restrictions. This shared engine may show a clearly marked fictional example while the historical visual remains pending.

### 6. Single-candle example integrity

For the approved fictional example: O=$31.00, H=$32.50, L=$30.50, C=$32.00. Show the actual candle, body, wicks and complete range. The body is $1.00; range $2.00; (body ÷ range) × 100 = 50%. The **Practice and Transfer displays must not pre-fill or reveal the final numeric answer** before checking the response. Any assisted explanation should be recorded as help in ungraded practice, never as independent official mastery.

### 7. Chart controls and no-look-ahead

The appropriate chart may expose completed OHLCV data, hide/show relevant annotations, select a candle and modify hypothetical input. Replay must use the authenticated server as chronological revelation authority for protected observations. Do not preload restricted future bars, put future prices in hidden HTML, or infer executions/motives from candles. Readable axes, intervals, legends, OHLC/volume inspection and mobile layouts are required when applicable.

### 8. Replay decision sequence

Show known observations → request interpretation → require a risk-aware hypothetical action → record forecast/uncertainty and rationale → lock the analysis → server-authorized reveal → assess the prior decision separately from forecasting accuracy → continue or conclude. Fictional Study Only replay never generates an official grade or historical-accuracy claim.

### 9. Free instructional assistance

Accessible instructional Labs must offer concept-aware **Explain This Concept, Teach This in More Depth, Show a Guided Example, Try Another Example, Explain My Mistake** as appropriate to the task. Help must explain symbol definitions (including Σ where used), data source, why the method applies, calculation with units, chart connection, common wrong approaches, interpretation and limits. Generic filler is insufficient. No Question Pass purchase is required for essential teaching and remediation in accessible Labs.

### 10. Assessment, credits, privacy and security

Maintain server authoritative authorization, reviewed scoring, Question Pass balances and policies, user-scoped records, grading disclosures and replay entitlements. The frontend must not grant official access, client-side mastery, imaginary credit balances, or unseen market information. Clearly distinguish public examples from premium member records.

### 11. Unified website integration

Labs load under the existing website header/navigation and through the in-site Lab Registry, preserving the Learn/Tools, Commons, Store, search, account, notifications, and return-to-Registry path. No duplicate nested headers or uncontrolled scrolling. Authorized direct bookmarked routes may remain. Do not break site commerce, support, administrator or forum functions.

### 12. Presentation and accessibility

Approved dark, structured visual treatment; chart-first where justified; compact controls; readable form labels, clear instructions, keyboard access, sensible focus, high contrast, responsive mobile and desktop layout, status announcements, and reduced-motion support. Technical notices are accessible but secondary to teaching.

### 13. Shared implementation architecture

One configured v3.3 engine owns stage progression, mode states, contextual visual selection, formula/validation, free teaching and error feedback, transfer/replay integration, and secure handoffs. Lab-specific authorized content, editorial metadata and approved source charts remain associated with stable canonical IDs. Reuse existing 30 competencies; no new master IDs.

### 14. Acceptance gates

For every applicable canonical Lab, maintain separately:
1. Source implemented.
2. Shared engine and browser regressions passing.
3. Subject instructional content reviewed.
4. Appropriate visuals present.
5. Historical data provenance / visual source approved when required.
6. Correct authorization, grading, privacy and no-look-ahead tested.
7. Live authenticated functionality tested.
8. Product-owner production acceptance.

**Neither mapping 419 IDs to the shared engine nor rendering fictional visuals satisfies the later gates.** Editorial evidence and real market source verification are independent, uncompleted tasks until proven.

### 15. Rollout and change control

Apply to the single shared engine first, test representative visual categories and modes, and reconcile all 419 curriculum records against the type-selection audit. The owner-approved VWAP-style layout is controlling; material changes require owner approval. Defer nonessential ideas outside v1.

### 16. Non-production illustration boundary

A fictional calculation or chart may be used in ungraded Learn/Experiment/Practice but must be labeled **FICTIONAL • STUDY ONLY**. It must not be inserted into private Assessment/Blind contexts as if authorized historical evidence. Server controlled replay and private results must remain separate.

### 17. Final requirement

A candle question needs its candle; a chart-reading task needs suitable price context; VWAP/EMA tasks need their relationship visual; tape/depth tasks need their correct representation; a replay requires lock-before-reveal; a wrong response needs remediation; and a result must distinguish assisted learning from assessed mastery. The system is a consistent interactive learning workstation, **not a collection of text-only questions**.
