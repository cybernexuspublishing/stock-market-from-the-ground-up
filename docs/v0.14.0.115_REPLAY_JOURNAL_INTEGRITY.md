## Corrected engineering contracts

1. **Synthetic vs historical provenance.** Original fictional bar sequences must not be journaled as “Verified historical replay”. The v115 single-file, Owner-review SQL supersedes the v94 installer for this function. It reuses the EXISTING `gu_replay_journal_links_v01494` table, RPC name, private grants and locked first-decision snapshot; it marks source type in immutable JSON and journal description. It does **not** mark an original simulation as authentic historical market data. Earlier v94-created records are not silently rewritten: their authoritative first-decision snapshot and immutable data must be inspected before correction. Existing v94 links remain idempotent.
2. **Decision/order consistency.** The backend independently rejects a simulated order plan on WATCH, NO_TRADE or OBSERVE, regardless of browser fields. The browser validates the same contract. ENTER remains optional order assumptions; no confirmed broker fill or P&L is generated.
3. **Bar integrity.** Server no longer sends non-positive OHLC prices, nonfinite timestamps or invalid bar indices. Historical rights metadata alone cannot justify a malformed visible bar.
4. **Private member changes.** On logout/account switch the replay client removes visible candles, stale links and session references, and discards in-flight responses from the former member. Token refresh for the same member does not erase the workbench.
5. **Journal readability.** Linked journal entries show a source note backed by the locked snapshot, including a backward-compatible `GUSIM_` fictional identifier check. Technical `historical_lab` classification on unverified journal-list entries is called “Replay / Historical Lab (review source)” until an authoritative linked source is opened.
