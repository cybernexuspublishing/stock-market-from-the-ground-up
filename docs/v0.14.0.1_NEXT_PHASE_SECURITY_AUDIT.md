# v0.14.0.1 — Sitewide Review, Controlled Security Patch, and Next Phase

**Status:** LOCAL SOURCE CANDIDATE ONLY; not deployed, no live Supabase execution, no live browser account tests, no payment activation. **Date:** 2026-10-13. **Source:** owner's exact v0.14.0.0 COMPLETE_SOURCE_PREVIEW archive.

## Evidence-supported changes

- **P0 Market Commons production-write bypass:** the published v0.13.1 Supabase `commons_create_topic` and `commons_create_reply` RPCs check `auth.uid()` and suspension but do **not** reject `profiles.account_kind='showcase'` or `test` nor active SHOWCASE_VIEWER roles. The Cloudflare middleware blocks `/api/*` Showcase POST, but Market Commons sends its writes *directly to Supabase*. That leaves the historical RPCs with a separate unprotected route. The additive `v0.14.0.1_FORUM_WRITE_AND_CHECKOUT_GUARDS.sql` replaces these two RPCs and adds restrictive policies on the retained legacy `forum_topics`, `forum_posts`, and `forum_reports` tables (as defense in depth if INSERT/UPDATE grants exist in a given deployment) with server-verified production-member checks, plus atomic per-member 24h quotas for modern Market Commons (10 topics, 60 replies by default; backed by existing Owner-administered site_settings).
- **P0/P1 book-text entitlements:** v0.14.0.0 `interactive-training.js` checks premium ONDEMAND_TRAINING entitlement but not matching paid/book-key access before delivering Book II rubric prompts or accepting answers. It now reuses existing server `getBookAccess` for every action, including resumptions and answers. Public sample instructional references remain separate; private answer keys remain on Supabase service role only.
- **P1 visibility/payment state coupling:** the v0.14.0.0 owner plan RPC could retain `checkout_enabled=true` when a previously hidden or inactive item is re-listed, if commerce is later enabled. The replacement requires a separately reviewed checkout rollout after re-listing. It never creates provider variants or activates payments.
- **P0 legacy demo grant/deletion path:** `/api/admin-v013?action=demo_create` creates genuine paid entitlement rows for demo users; `demo_delete` targets accounts with `+demo-` in the email address, risking deletion of a legitimate account. Both legacy actions are denied by middleware until synthetic TEST account functionality is verified.
- **P0 forum reporting schema compatibility:** historic v0.5 `forum_reports` required `reporter_id` and exactly one legacy `topic_id`/`post_id`, while v0.14 report RPC inserts `reporter_user_id` and `content_id`; old status validation also rejects `reviewing`/`resolved`/`dismissed`. On deployments with this migration history, reporting and moderation would fail. The new migration conditionally relaxes only recognized old constraints, preserves old rows and adds a unified validation rule; unknown target constraints abort the SQL transaction for manual review. Confirm the actual preflight constraint definitions before applying.
- **P0 Market Commons official-guide authenticity:** `commons_topic_save` allowed any moderator with `forum.moderate` permission to create purported official platform guides and turn member discussions into official guides. That route now requires an actual OWNER and refuses conversion of non-official content. Existing moderation workflows continue.
- **QA/test isolation:** archived `test_branch_inclusion.py` hard-coded version v0.13.5.7.5 and the now-private `data/interactive-labs.json`, so `pytest` fails at collection for v0.14. Retained the archived test assertions and skips it for nonhistoric releases. Added v0.14.0.1 authorization test and targeted book-entitlement mock.
