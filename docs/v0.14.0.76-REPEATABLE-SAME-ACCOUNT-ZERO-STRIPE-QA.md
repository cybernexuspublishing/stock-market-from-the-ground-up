## Behavior
- The **one** allowlisted account configured in Cloudflare `GU72_QA_ALLOWED_USER_ID` stays the same across cycles. No changes to the eight paid membership SKUs or to the separate active zero-dollar LIVE Price.
- A signed, verified `checkout.session.completed` grants one nonrecurring month of `FULL_MONTHLY` per NEW Checkout Session. A given `cs_live_...` can **never grant a second time**, even if the grant was intentionally canceled; old grant rows and Stripe session references remain as replay audit evidence.
- While the QA membership is active, the Store shows **Reset this test membership to FREE for another checkout** to that *same, signed-in* allowlisted member ONLY when both GU72 QA switches are enabled. The reset requires explicit confirmation, ends **only** active source `stripe_zero_monthly_qa_v72` plan grants immediately, leaves Stripe transactions, paid memberships, book rights, subscriptions, other plan sources, identities and provider ledgers untouched.
- Once membership is back to `FREE`, a **new** $0.00 checkout can be initiated. Each deliberate click uses a newly generated `checkoutAttemptId` for the Stripe idempotency key, replacing the previous **per-member/per-calendar-day** key that reused an already-completed Stripe Session. Clicking again the same day therefore creates a NEW Session; network retries with the same attempt ID remain provider-idempotent.
- The original eight-product GU58 live launch flags remain locked. GU72 LIVE-only test remains one allowlisted member at a time and still requires explicit `GU72_ZERO_MONTHLY_QA_ENABLED=true` and `GU72_ZERO_MONTHLY_FULFILLMENT_ENABLED=true`, a verified $0 LIVE Price, and a real signed webhook.

## Safety and scope
- The reset is **not** a manual payment refund, subscription cancellation, password change, or blanket grant deletion. Its sole SQL update is to the active FULL_MONTHLY grant rows with source `stripe_zero_monthly_qa_v72` and matching allowlisted member UUID.
- The action is **not a public free membership offer**. Only the exact Cloudflare allowlisted, verified adult FREE/member identity can checkout; while it has a QA grant, only that same account can reset that QA grant.
- The new Checkout is still an actual Stripe LIVE operation with `amount_total=0`, no PaymentIntent, and no recurring subscription. It cannot certify recurring invoices or paid charges.
- Source tests and GitHub checks do not certify the live installation or real Stripe delivery. Real end-to-end PASS requires that the account transitions `FULL_MONTHLY → FREE → FULL_MONTHLY` and a second genuine Stripe-signed event is processed for the new Session.
