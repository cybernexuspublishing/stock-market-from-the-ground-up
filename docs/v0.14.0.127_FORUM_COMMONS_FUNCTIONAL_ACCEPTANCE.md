## New defect corrected in v127

`functions/api/forum-member-content.js` denied access whenever it saw a `SHOWCASE_VIEWER` row, even if the role expired. By contrast, the v116 PostgreSQL RPC already treated only non-expired or indefinite Showcase roles as active. As a result, a valid production member with an expired temporary Showcase role could never reach an otherwise authorized edit or delete operation. The route now reads `expires_at` and applies the same active-role predicate. Indefinite and unexpired Showcase roles, suspended/restricted flags, and non-member account kinds remain denied.

## New automated acceptance (disposable database only)

`tests/fixtures/v014127_forum_functional_authorization_acceptance.sql` adds PostgreSQL 16 cases not provided by the v125 fixture:
- Cross-member Forum edit must be denied without an audit side effect.
- Stale version must conflict; no edit or audit record created.
- Active Showcase is blocked; expired Showcase plus healthy account is allowed and audited.
- Suspended accounts remain blocked even after Showcase expiration.
- Member reply edit is denied during a moderator-held parent lock, without an audit side effect.
- Authorized member soft-delete is audited.
- Members and non-owner moderators cannot alter official Market Commons guides.
- Authorized moderator hides an ordinary Commons reply with one attributable audit entry.

The new workflow `.github/workflows/forum-functional-acceptance-v014127.yml` runs the existing v125 disposable setup as a prerequisite, then the additional v127 scenarios. **It does not run against production and never imports production accounts or forum content.** It also runs the edited API regression tests for indefinite, active, and expired Showcase roles.
