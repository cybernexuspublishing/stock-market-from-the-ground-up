# v0.14.0.9 — Admin Control Registry and Runtime Ownership Audit

**Source:** complete v0.14.0.8 repository ZIP. **Status:** implementation candidate; not production-certified. **Changes to production:** none.

## Confirmed root cause

Previously at least four different scripts attempted to own the Admin sidebar, using different initialisation times and different fixed lists. This produced disappearing controls, multiple/renamed groups, and stale release badges even after GitHub source cleanup. Deleting retired files cannot fix an actively loaded legacy script that still mutates the same DOM.

| Script | Before | Now |
|---|---|---|
| `assets/js/frontend-complete.js` | `rebuildAdminGroups()` reconstructed `#admin-tabs` after a delay | Group reconstruction retired. Other page/admin features retained. |
| `assets/js/production-completion.js` | `reorganizeAdminGroups()` re-parented buttons to a static set of groups | Group reconstruction retired. Support/QA/Archive panels retained. |
| `assets/js/admin-legacy-routing.js` | `groupNav()` constructed groups from older hardcoded lists | Group construction retired. Forum, catalog, academy panel implementations retained. |
| `assets/js/admin-navigation.js` | Re-grouped links after other scripts (could be undone by earlier delayed mutation) | Sole sidebar presentation owner. Displays every installed eligible control, including later-inserted controls; no old component can rebuild the sidebar. |
| `functions/_middleware.js` | Could inject `admin-navigation.js` a second time | Uses `admin.html`'s single static script reference. |
| `assets/js/frontend-complete.js`, `layout-integrity.js`, `frontend-freeze.js`, `_middleware.js`, `admin.html` | Fallback/injected version names could diverge | Version source/fallbacks aligned to `v0.14.0.9`. Service-worker cache namespace updated. |

**Important:** Retiring competing Admin sidebar *grouping* does not mean the website has only one DOM mutation script globally. Other scripts still dynamically render their own module panels, cards, notifications, product listings, etc. Their module boundaries must continue to be reviewed; a guarantee that no other component anywhere can ever conflict requires complete end-to-end browser testing. The current scope is the confirmed sidebar and version-collision class.

## Owner-managed control registry

A new Owner-only **Manage Admin Controls** interface permits:

- Rename, reorder, assign categories and hide/show installed Admin controls without deleting their implementation.
- Add custom shortcuts to **existing internal pages**. It does **not** invent a page, database contract or backend capability.
- Remove Owner-created shortcuts; existing controls can be hidden but not deleted by this interface.
- Preserve Dashboard and control-manager recovery paths.
- Retain permission gating. Hidden links are presentation preferences, not grants or revocations of authorization.
- Persist settings in dedicated `admin_control_registry_v01409` table with RLS enabled, direct browser roles revoked, and transactional audited writes via `v01409_admin_control_save`.
- Prevent suspended/restricted, TEST, SHOWCASE, non-Owner and non-MFA-verified Owner requests from modifying settings.

## Deployment procedure (Owner manually controls production)

1. Preserve a GitHub commit for rollback and a verified Supabase backup/restore point.
2. Run `supabase/admin/v0.14.0.9_ADMIN_NAV_READ_ONLY_PREFLIGHT.sql`. Every result must be true. If false, reconcile the missing object instead of skipping it.
3. Run the additive migration `supabase/migrations/v0.14.0.9_ADMIN_CONTROL_REGISTRY.sql` in the **existing** Supabase project. It adds no member entitlement, no new purchases and no historical-data changes.
4. Upload the complete versioned ZIP to the existing GitHub repository on a preview branch. Build command `bash scripts/build-pages.sh`, output `public`. Ensure server `functions/` remains at repository root.
5. Verify Owner's `Manage Admin Controls` shows all installed links; test rename, category, reorder, hide, restore, custom add/remove; test with a second Owner session, and with non-Owner/TEST/SHOWCASE/suspended sessions. Confirm Dashboard, Reports, Account Management, Instructor, GWS and Site Operations still work.
6. Deploy to `main` only once the preview tests pass. Re-test after a hard refresh/service-worker update.
7. Retain the pending **v0.14.0.7 SQL B** lockdown sequence: only execute SQL B after both forum reporting interfaces are proven to work on the deployed version. v0.14.0.9 does not execute or replace that earlier migration.

### Scope limitations

The navigation manager is **not** a drag-and-drop website builder, universal new-module code generator, substitute for backend permissions, or proof all administrative workflows are complete. It solves an essential extensibility problem and prevents the known source-level sidebar rewriter collisions. Full Grant Web Solutions client isolation, advanced module lifecycle, media/asset publishing, payment lifecycle and complete 419-Lab answer verification remain separate requirements.
