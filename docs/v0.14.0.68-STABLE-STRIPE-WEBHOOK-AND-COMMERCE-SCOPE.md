## Permanent webhook destination

**LIVE membership and individual-tool subscription endpoint:** `https://stock-market-from-the-ground-up.pages.dev/api/stripe-live-webhook`

File `functions/api/stripe-live-webhook.js` delegates to the existing GU58 signed, merchant-account-checked, idempotent membership fulfillment handler. Internal code versions may change without a Stripe endpoint URL change. The historical `/api/stripe-live-webhook-v01458` remains temporarily routable for delivery continuity, but **must NOT be configured as a duplicate active LIVE Stripe event destination**. If an older LIVE destination exists, edit/rotate its URL in Stripe, rather than creating duplicate subscriptions. Before decommissioning any previous endpoint, check provider delivery history and the old endpoint secret; never lose already-arrived or queued events.

The new route is deployed **disabled for fulfillment** until the Owner separately authorizes `GU58_LIVE_WEBHOOK_ENABLED`, `GU58_LIVE_FULFILLMENT_APPROVED` and `GU58_LIVE_DB_CONTRACT_APPROVED`. Creating the Stripe endpoint alone does NOT authorize those switches or actual charges. Stripe delivery while disabled may receive HTTP 503; a legitimate payment must never be initiated until webhook and entitlement acceptance is verified.

### Eight event types for GU58 LIVE membership / tool fulfillment

`checkout.session.completed`, `checkout.session.async_payment_succeeded`, `invoice.paid`, `invoice.payment_failed`, `customer.subscription.updated`, `customer.subscription.deleted`, `charge.refunded`, `charge.dispute.created`.

Choose events from **Your account** (not Connect) in **LIVE** Stripe Dashboard → Workbench → Webhooks/Event destinations → Add destination. Use an HTTPS **Webhook endpoint**, Snapshot/event object payload compatible with the existing handler, and the permanent URL above. Select the eight types individually, not wildcard `*`. After endpoint creation, securely store the endpoint-specific LIVE `whsec_` secret under Cloudflare `GU58_STRIPE_LIVE_WEBHOOK_SECRET`, never in a file, chat or GitHub. The merchant API secret uses the existing `GU58_STRIPE_LIVE_SECRET_KEY`, always a Cloudflare encrypted secret. Set `GU58_STRIPE_LIVE_ACCOUNT_ID` to the matching LIVE `acct_` ID. **Keep TESTING ACTIVE and all LIVE checkout/fulfillment authorization flags OFF** while configuring the catalog and webhook.

### Other Stripe payments

The **personally signed KDP author-copy physical books** already have a *different*, permanent endpoint `https://stock-market-from-the-ground-up.pages.dev/api/signed-book-stripe-webhook`, controlled by `STRIPE_SIGNED_WEBHOOK_SECRET`, `STRIPE_SECRET_KEY`, `STRIPE_SIGNED_TEST_MODE` and independently disabled sales settings. That separate handler uses a **different order/fulfillment/physical tax/shipping contract**; it must not be routed into GU58 membership entitlements. If it becomes active on the **same Stripe account**, overlapping webhook event subscriptions may deliver unrelated checkout/refund events to GU58; **cross-product routing and ignore semantics must be reviewed and regression-tested before enabling either LIVE checkout**. Register only the GU58 membership endpoint in this phase; do not claim that one GU58 endpoint fulfills books.

### Critical configuration boundary

`GU58_STRIPE_LIVE_CATALOG_JSON` currently requires **exactly eight** keys (four memberships and four tools), each containing `{product_id,price_id}`. **Adding ebook, signed book, Free, Lulu, or future SKUs to this JSON will cause GUARDED LIVE checkout and the v67 merchant audit to fail closed.** Additional products should be entered into their own catalog/provider/rights registers with independent webhook and fulfillment routing. Do not change the existing eight-product membership contract as a shortcut.

The screenshots dated October 16, 2026 recorded eight `prod_` Product IDs without independently certifying whether they were LIVE or TEST, while later Owner-reported `price_` IDs were described as LIVE. This release does **not** claim that these identifiers have been cross-verified against the actual LIVE Stripe API. The Owner must use the v67 review after storing a tentative Cloudflare catalog, then reconcile any mismatch from the real LIVE Stripe Price object's `product` field. Do not copy TEST IDs into LIVE.
