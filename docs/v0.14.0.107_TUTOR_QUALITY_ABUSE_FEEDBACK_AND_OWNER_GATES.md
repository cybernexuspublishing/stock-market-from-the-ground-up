## Actual findings and corrective implementation

1. **Guide starvation:** Previously any glossary match suppressed all 30 competency guides. The Tutor now consults both source catalogs for every non-advice teaching question, enriches public matches with deterministic synonym expansion, and when original guide evidence matches it grounds the answer in procedures, invalidation and uncertainty plus applicable glossary descriptions. The 5-minute, per-binding in-memory cache holds public source JSON only, never member history or unpublished rubric.
2. **Citation defects:** Removed mandatory `[1]`; accepted model output must contain at least one real valid ordinal `[n]` among the exact 1–3 references supplied. Out-of-range citations, empty citations, overlong responses and selected actionable trading recommendations are rejected in favor of existing source-grounded teaching. This is still a structural check, **not** full claim-by-claim citation faithfulness.
3. **Advice/injection:** Both the question and separately typed learner reasoning are checked for personalized trading/price-target requests before AI quota reservation. Outgoing model responses receive another conservative decision-directive scan. Previous client-submitted pseudo-“Tutor” turns are discarded and never enter model input; the member may continue a topic through their new question. Regex guards do not replace red-team review or an investment-advice legal assessment.
4. **First-party provider boundary:** An explicit allowlist adapter supports currently configured OpenAI Responses inference (`AI_TUTOR_PROVIDER=openai`, optional because the adapter defaults to this sole supported provider). The first-party service is owned and administered by the company; the underlying pretrained model is not. Unsupported adapters fail closed before request reservation. Existing `AI_TUTOR_API_KEY` and `AI_TUTOR_MODEL` remain server-only. API `store:false`, output/token limits and timeouts remain in force.
5. **Non-sensitive diagnostic events:** The Tutor emits structured runtime event/reason/source-count logs, NEVER user IDs, prompts, reflections, request IDs, vendor API keys or personal account history. The Cloudflare operational log sink, retention/alerts and central cross-run reporting still require actual deployment validation.
6. **Global availability:** Member AI status now checks their own budget plus both site-wide daily/monthly budgets using private PostgREST exact-count headers. A broken meter fails closed for paid inference; the screen does not advertise provider availability on an exhausted global cap. Reserved attempts remain chargeable against v103 quota after provider failure; refunding paid requests requires a separately reviewed financial/audit policy.
7. **Authentic conversation records:** The model/Tutor service, not the member browser, now persists optional member-selected replies using the already-installed v102 private RPC. Saved replies receive a `verified:` generation prefix. Older member-copied rows remain accessible and explicitly labeled legacy/unverified. The public history endpoint refuses browser POST uploads; member-owned GET/DELETE are preserved. The server-saved response is authentic as the system's reply, but does not certify pedagogical accuracy, licensed history or immutability.
8. **Private feedback:** Members can mark saved replies helpful/not helpful or report an answer, optionally adding <=500 chars of explanation, via user-scoped authenticated PATCH in the existing private history API. No grading or competency evidence changes. Private SQL v107 adds the feedback columns; without it legacy history GET still works and the UI reports that feedback was not saved.
9. **General abuse throttling:** The optional v107 rate bucket SQL serializes per-member writes and enforces 8 source/practice Tutor requests per minute and 120 per UTC day, using a **single bounded row per member**. It does not mix free tutoring with the paid v103 request ledger or consume AI provider credits. Until v107 is installed, zero-cost instruction remains available but general throttling is **not** enforced by that SQL. Paid inference remains independently fail-closed behind v103 caps. Do not claim that browser IP-bot protection is complete.
10. **Golden tests:** Versioned, source-only educational fixtures check glossary/guide/synonym coverage, investment advice prompts, citation `[2]`, invalid citations, simulated model recommendations and privacy. They run with mocked authentication/provider; they do not establish human-approved educational correctness or funded provider acceptance.

## Commercial provider activation, still independently gated

For any **real funded model call**, the Owner must verify in the actual server environment the existing v103 DB meter, `AI_SERVICE_ENABLED=true`, `AI_TUTOR_API_KEY`, `AI_TUTOR_MODEL`, all three named `AI_SERVICE_*_LIMIT` settings and a provider-side monetary spend cap/alert. The code does not set these secrets, activate checkout, acquire credits or spend paid tokens. A site-wide request count is not an actual USD invoice.

For account data, approve published privacy/retention/erasure policy, provider prompt handling/disclosures, old member-copied note status, and refund/appeals process for wrong AI answers. The history table is private but not claimed to be cryptographically E2EE or immutable. Active paid access is currently required to view old Tutor notes; data portability independent of entitlement remains a compliance issue.

## Unresolved engineering defects

- **Durable operational logging:** Cloudflare observability (stream/retention, anomaly alerts, trace sampling, incident reports) is not installed or confirmed merely by emitting safe reason codes.
- **Verified claim faithfulness:** No automatic factual citation/entailment or human instructional evaluation across the 419 Labs; the golden set only checks narrow mechanical invariants.
- **Rate limiting before v107 SQL and anonymous clients:** The existing authenticated Tutor source rate limiter is optional during rollout, not a platform-wide WAF/Turnstile replacement.
- **User feedback moderation:** Privately collected flags require actual editorial triage, case workflow, data-retention rules, and a provider escalation path.
- **Provider costs and refund decisions:** A reserved slot remains spent when the model fails. A credit/reconciliation mechanism must avoid race conditions and budget bypass, and cannot simply delete audit events.
- **Non-tutor tasks:** Atomic forum moderation+audit, published and crawlable legal policy content, verified historical market licensing, robots/sitemaps, installable PWA icons, restrictive CSP, automated backups/recovery and all eight live commercial entitlements remain independent launch blockers.
