## Implemented in this release

The existing Admin Control Center → Commerce / Payments & Billing section now has a collapsible **LIVE Merchant & Eight-Product Readiness — No Charge** area and one Owner-only **Run LIVE Merchant Review — No Charge** button. It reuses current Owner login and the approved password step-up, without adding any new credentials to the browser.

**Endpoint:** `GET /api/stripe-live-merchant-readiness-v01467`. It performs only Stripe REST GET and selected read-only Supabase GET, plus existing **role and step-up verification RPCs**. It does not use a new Supabase project, enable checkout, change payment mode, create test identities, post to Stripe, initiate charges, subscribe members, insert events or mutate databases. The POST route explicitly returns HTTP 405. Unauthorized users receive an error without any Stripe credential inspection. All results are `private, no-store`, and return status summaries only—not secret keys, raw account information, webhook secrets, customer IDs, or full onboarding requirements.

The report checks:
- Cloudflare LIVE secret-key **format**; matching configured LIVE Stripe account ID; complete/distinct eight-element LIVE Product/Price map; webhook signing-secret **format**; canonical HTTPS production URL.
- Existing Owner TEST/LIVE mode is **observed, not changed**.
- LIVE account identity from Stripe; `charges_enabled`, `payouts_enabled`, `details_submitted`, requirement counts, and account-reported `card_payments` capability. Missing API fields are **UNVERIFIED**, not presumed ready.
- All eight canonical database offer amounts/cadences against actual LIVE Stripe Product and Price objects. As in GU58, only active USD fixed `per_unit`, no quantity transform, licensed recurring at exact `interval_count=1`, or one-time Lifetime passes. Locked membership checkout flags are NOT an obstacle to **read-only audit**.
- Exactly one enabled LIVE webhook destination matching the canonical public site and **all eight explicitly selected required event subscriptions**. An incomplete list or wildcard-only event subscription is reported as REVIEW, never silently certified.

**Not verified by read-only calls:** Stripe Managed Payments preview permission, actual webhook signature-secret pairing/delivery, complete merchant eligibility for specific offerings, deployed SQL function-body equality to source, actual payment-to-entitlement lifecycle, taxes/terms, refund/dispute processing, or Owner-authorized live launch. The API always returns `liveCheckoutApproved:false` and `readyForLiveCheckout:false`.

## Required Cloudflare server-side configuration to run remote checks

All existing GU58 names are unchanged, and values must be stored **only** in Cloudflare Pages server-side settings (never GitHub, browser, chat or SQL results):

`GU58_STRIPE_LIVE_SECRET_KEY` (Stripe LIVE secret), `GU58_STRIPE_LIVE_ACCOUNT_ID`, `GU58_STRIPE_LIVE_CATALOG_JSON` (all 8 distinct `{ "plan:FULL_MONTHLY":{"product_id":"prod_...","price_id":"price_..."}, ... }` entries), `GU58_STRIPE_LIVE_WEBHOOK_SECRET` (LIVE `whsec_` value), optional canonical `PUBLIC_SITE_URL`.

**Do NOT enable** `GU_PAYMENT_LIVE_LAUNCH_APPROVED`, `GU58_LIVE_CHECKOUT_ENABLED`, `GU58_LIVE_FULFILLMENT_APPROVED`, or `GU58_LIVE_DB_CONTRACT_APPROVED` to use the diagnostic. Existing secret permissions must allow necessary Stripe GET endpoints; permission denial remains UNVERIFIED.

The configured LIVE webhook, once authorized, will use the existing `/api/stripe-live-webhook-v01458` endpoint. **Do not enable** real signed fulfillment until approved lifecycle acceptance; historical real subscriptions, if any, require a different ongoing reconciliation policy.
