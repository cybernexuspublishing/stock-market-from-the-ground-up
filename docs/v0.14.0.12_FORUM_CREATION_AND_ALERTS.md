# v0.14.0.12 — Forum Creation, Quick Replies & Unified Alerts

**Source baseline:** v0.14.0.11 complete repository. **Scope:** existing Cloudflare Pages frontend, no new database objects. **Production:** not deployed or verified.

## Root cause and remediation
- `frontend-complete.js` previously owned an Alerts button, while `production-completion.js` installed a **capturing** `click` handler on that same button and called `stopImmediatePropagation()`. The older script intercepted the button, displaying only `user_notifications` and never Site Announcements.
- Retired the duplicate capture handler in `production-completion.js`. `frontend-complete.js` is the sole owner of the button and dialog. This repairs a real active-script conflict instead of layering a new notification system on top.
- `Alerts` now displays two distinct sources: time-window- and audience-filtered announcements from `/api/site-announcements`, and authenticated account notifications from `/api/ui-state?action=notifications`. A failure in one source does not suppress the other. Guests see public announcements. Unseen announcement badges are local to browser/user; notification read status continues to be stored server-side. No direct HTML is rendered from announcements.
- Restricted notification links to same-origin paths, not arbitrary schemes. Site announcements retain the server's 60-second refresh design. No push/email messages are generated.

## Forum creation changes
- Shared `assets/js/forum-composer.js` provides actual text editing, safe BBCode, formatting tools (bold, italic, underline, strikethrough, quote, code, lists, links), emoji insertion, character counts, and live preview on both the modern Market Commons and the original legacy Forum/Topic pages. The modern Market Commons is the canonical `/forum.html` redirect destination.
- Market Commons New Discussion modal now has organized sub-forum/ticker/title fields, descriptive posting rules, topic icons, keyword entry, and improved responsive layout. Icons are stored as the title prefix and keywords are stored as searchable text at the end of the body; these are not separate database metadata fields. Native modal Cancel and keyboard submission are supported. Existing `commons_create_topic` authorization remains unchanged.
- New-discussion and reply rendering supports a deliberately constrained, escaped BBCode subset; arbitrary HTML and unsafe link schemes are not rendered as HTML. Original author body is shown as a safe quote insertion option on modern and legacy topic replies.
- Modern Market Commons has a recent-replies snapshot restricted to posts and parent topics visible through Supabase RLS; existing pagination, forum sections, pinned labels, user reporting and linked Historical Labs are preserved.
- Original forum now has an expanded structured new-topic editor and a quick-reply toolbar. Legacy forum route still redirects to Market Commons in Cloudflare middleware; those pages are maintained for compatibility with deep links.

## Intentionally NOT represented as complete
- File attachments: no unverified uploads, media scanning, archival uploads, storage ACLs, virus processing, or thumbnail jobs have been added. Such a feature requires private object storage, authorization and content safety reviews.
- Poll voting: no polls or votes have been added. A real poll requires tables/RLS/transactional votes/expiration/anti-abuse controls; no cosmetic poll checkboxes.
- Reply subscriptions: no reply notification trigger / delivery service has been added. Pre-existing `commons_topic_subscriptions` schema is not a substitute for a working notification delivery workflow.
- Actual production posting, Alerts API calls, database permissions and moderation remain unverified until the Owner tests a Cloudflare preview/production deployment.
