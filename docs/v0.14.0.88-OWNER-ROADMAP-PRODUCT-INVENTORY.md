## Requirements and design

The existing **Project commitments**, **Detailed requirements source**, and **Reference lines** tabs are preserved verbatim. Two additional Owner-only tabs are added:

1. **Tools & Development:** Read-only inventory of *all existing Supabase tool records* (not only the four current separately priced live offers), including non-public and unreleased items (marked as such). Each entry shows code, name, category, description, catalog status, eligibility-based indicative price, free-preview flag, data requirements, learning outcomes, supported first-party route, and expandable acceptance work. Four current paid codes are `INTERACTIVE_LEARNING`, `JOURNAL_ANALYTICS`, `MARKET_SIMULATOR`, and `MARKET_TUTOR`. Distinguishes **supporting learning capabilities** from independent Stripe SKUs: Learning System / Skills, Historical Labs, Skill Assessments, Sample Labs, Historical Replay Training, Data Connections, and Market Commons/community. Route existence is not a claim of complete functioning, a paid product, or launch certification.
2. **Membership Inclusions:** One review card for *every actual Supabase membership* (not only publicly advertised plans), with price/cadence from Supabase, explicit active/visible/checkout switches, the *reviewed* customer inclusion list, exclusions, learning outcomes, billing/access disclosures, database flags `includes_all_tools` and `includes_all_books`, and the mapped released tool names. An expandable, horizontally scrollable **feature-by-membership comparison matrix** checks the `plan_tool_access` table and inheritance rules; unmapped tools are shown as not configured, not silently granted. Free previews are identified separately from a paid entitlement. The dedicated Historical Replay Monthly membership retains its exclusion of the proprietary simulator and all Full Platform tools.

**Owner development flow:** Every tool and membership has an **improvement task** button. It fills the *existing* private Owner task form with its actual product ID, a scope, and measurable risk/QA acceptance requirements. **No task is created until the Owner reviews it and selects Add task**, preserving existing revision controls, audit and task ID semantics. Existing Owner-saved and delegated milestone statuses are unchanged.

## Data architecture and privacy

The existing server-side `GET /api/owner-roadmap` authenticates the actual Supabase user and verifies eligible **OWNER** role, optional MFA, and account status before accessing the new read-only queries. The private response includes one `productInventory` payload read from the actual `platform_plans`, `platform_tools` and `plan_tool_access` tables using the existing server-only Supabase key, with explicit finite columns/row limits. No new database, new SQL migration, test product, Stripe product, checkout session or grants.

Reviewed educational copy comes from the existing v0.14.0.84 Store product-guide data, maintained as an exact synchronized snapshot in `functions/_lib/owner-roadmap-product-inventory-v01488.js`. **CI fails if membership/tool guides drift from the Store editorial source.** No Store copy, books, KDP records, prices or live checkout flags are changed.

The HTML contains **empty tabs only**: private inventory information is sent **only after Owner authorization**. The server lib is not published to Cloudflare's static `public/` output. Owner GET responses are `Cache-Control: private, no-store`, and no localStorage records are created. If a live catalog query fails or truncates, the tabs clearly show an **unavailable/not verified** state and never promote cached price/entitlement assumptions. The original roadmap task system still loads.

All extra surfaces are labeled as *supporting features* and distinguished from market subscriptions and paid products. Review of trading accuracy, licensed data rights, risk disclosures, brokerage/provider representation and external data feeds is a required development acceptance gate, not a statement of approval.
