### Owner membership behavior

`active=false` blocks *new assignments* and public plan selection. `public_visible=false` removes plan from public catalog/store lists. `checkout_enabled=false` blocks provider checkout for the item. These are independent controls. Old member grants are not automatically canceled: the existing entitlement SQL joins plans for benefits without requiring the plan itself to be active. **FREE** remains the protected account fallback; it can be hidden from the public pricing interface but should not be disabled as an internal default. Founding plans are **drafts at $49.99/month and $499/year** and are not activated by this patch. Payment-provider contracts, term length, subscriber counts, and tax configuration still require deliberate approval.

No v0.14.0.4 *write* migration was added; this release uses already-declared v0.14.0.0 plan RPC and existing profile/flag tables. The read-only `supabase/admin/v0.14.0.4_SAFE_CONTRACT_INSPECTION_READ_ONLY.sql` is included to inspect the live database without touching customer records.

## SQL provenance and application constraints

The uploaded ZIP includes migration sources for v0.14.0.0, .1, .2 and THREE .3 migrations. Source files do **not** establish that these have been applied to production. Use the `v0.14.0.4_SAFE_CONTRACT_INSPECTION_READ_ONLY.sql` first. Do not run earlier cumulative versions blindly. Private book-authored/answer-key seeds are deliberately not included in the public repository. **If the private seeds have not already been applied, the reviewed instructor cannot offer its graded path, and it must fail closed.** No new SQL write query is required for this v0.14.0.4 hardening itself.

## Testing claim boundaries

Running JS parsers, static asset refs, API mocks and browser fixtures proves those specific scenarios only. It **does not** prove Postgres transaction semantics, payment processor behavior, market-data authenticity, remote concurrency, mobile assistive technology acceptance, real user-data privacy, or deploy health. No website launch/deploy/cloud DB modifications were performed.
