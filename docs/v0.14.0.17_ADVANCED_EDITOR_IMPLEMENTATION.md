# v0.14.0.17 — Advanced authoring implementation, security review, and integration gates

## Baseline and integrity
This **updates the unreleased v0.14.0.17 drop-in** for the deployed v0.14.0.16 repository. It is **NOT a full repository ZIP**. The owner retains their existing Git checkout, all backend migrations, learning experiences, inventory, and Cloudflare environment variables. This archive only replaces the exact public runtime files listed in `docs/FILES_TO_REPLACE.txt` and includes quality checks and diagnostic docs. Never deploy this archive as an entire Cloudflare repository by itself.

## Implemented locally and verified in Chromium
- Shared editor: explicit `data-forum-composer` / `data-rich-content` integration contract, dynamic form discovery, source editor and accessible toolbar. Existing Forum, Market Commons, member edit, Owner announcements and Owner-created direct member notices are covered.
- Editor modes: basic text, BBCode, **visual contenteditable editing**, safe HTML-to-BBCode import, and rendered preview. Visual mode serializes to plain BBCode on mode change/submission; raw event handlers/scripts cannot be persisted by the editor.
- Formatting: bold, italic, underline, strike, allowed named and hex colors, allowlisted fonts, sizes, highlight, align left/center/right/justify, indent, horizontal rule, bullet/numeric/alphabetic/Roman lists, nested quotes with optional attribution, code, PHP/HTML code *display*, noparse, language attribute, spoilers with custom titles, safe links and emails, member mention *visual labeling*, inert member-submitted trading ticker/timeframe/risk/evidence/citation labels, anchors, table rows/cells, up to 12 external-image gallery items, image alignment, emojis.
- Images: HTTPS URL rendering is consent gated for readers. Browser loads the URL only after user action on the published view. Directly authored HTML source and visual editor may display the image in preview. No file uploads are enabled by this release.
- Private drafts: save/restore/discard button and explicit opt-in autosave using **sessionStorage only**; a closing tab/browser can discard them; drafts are never sent to Supabase. Staff should not store sensitive personal data in shared-device drafts. An existing field with content will ask for confirmation before restore.
- Security: strict URL scheme, explicit tag mappings, text/attribute encoding, restricted sizes/fonts/colors, no arbitrary HTML/JS/CSS, no iframes, script elements discarded from pasted HTML, readable focus/keyboard controls; no new database grants or auth changes.

## Feature status — no unsupported claims
Fully implemented and locally tested in this package: the above editor and rendering functions, previews, draft controls, client-side safe HTML import, deliberate partial gallery rendering, and announcements/notifications formatting.

Existing production code **not changed or revalidated** in this package: forum new thread/reply RPCs, member edit/delete API, admin moderation, existing private member alerts, registered-account authorization, existing Commons bookmarks/subscription storage and checkout restrictions.

**Not implemented / not enabled by the editor alone** (optional candidate SQL and UI add polls/votes/thanks/ratings/subscriptions after review, but these were not deployed or integration-tested): upload local files, drag-drop/clipboard image uploads, remote-URL file ingest, anti-malware scanning, size/type/quota enforcement and private object downloads; polls and voting, per-post thanks and thread ratings; post version history and diff; thread prefix/post icon persistence; robust forum tags and category search; quote multiple selected posts; mention notifications; subscription-based reply notifications; author profile/post-count/thanks summary; thread-specific search, multi-layout view, print/email integration, staff messages and appeals management. `attach` BBCode renders a truthful unavailable state, not a fake file.

Also not promised: executing pasted HTML/JS, arbitrary iframes, private image uploads, direct payment activation, new trading signals or broker orders. Source code display `[html]` is inert.

## Prerequisites for full vBulletin-class parity
**P0 AUTH + DATA**: full current 0.14.0.16 repository snapshot, controlled schema snapshots, member/Moderator/Owner/Showcase test accounts, anti-abuse limits, security-definer rights/RLS and private educational context isolation before *any* forum-data migration.
**P0 ATTACHMENTS**: authenticated object upload with virus/malware scanning or quarantined approval, content disposition protections, Storage RLS, signed viewing, quotas/rate limits, retention, removal and appeal procedure, policy for third-party image URLs and copyright complaints. Never accept HTML/SVG as uploadable active content.
**P0 REVISIONS**: append-only per-post revision table, transaction-bound log of member/staff edits, immutable actor/reason and timestamp, rollback policy, per-user visibility and privacy/data-retention controls. Client-generated history alone is insufficient.
**P1 POLLS**: normalized polls/options/votes with single- or multi-choice, exactly-once vote transaction locking, configurable close time, eligibility from category/access grants, privacy of nonpublic individual votes, audit, and idempotent UI. Historical Lab spoiler safeguards required.
**P1 INTERACTIONS**: thanks, thread rating, per-topic subscriptions, precise reply notifications, post permalinks and author posts/profile views. Notifications must respect member preferences, avoid duplicate delivery and preserve member privacy.
**P1 AUTHORING METADATA**: category-scoped prefix/icons/tags in DB and backend; searchable indexes and quotas; staff editorial controls and member edit windows; autosave recovery across devices requires authenticated draft API, encryption/retention constraints.
**P2 ACCESSIBILITY + QUALITY**: WCAG 2.2 AA independent review, mobile 320px+ tested, touch/keyboard/focus/SR behavior, p95 interaction latency, abuse-rate tests, backup/recovery rehearsal, pagination/load tests.
